# ToolBox 技术栈与概念详解（学习指南）

> 配套阅读：`docs/操作手册.md`（项目结构/逻辑/打包/使用，偏实操）
> 本文档：把项目里用到的**技术栈和核心概念**逐个讲透，供系统学习。
> 阅读顺序：第 1 节（架构心智模型）→ 第 2/3 节（前后端技术栈）→ 第 4 节（核心概念）→ 第 5/6 节（调试与学习路线）。

## 1. 架构心智模型（先建立这张图）

```
┌────────────────────────────────────────────────┐
│  ToolBox 桌面应用（Tauri 2）                     │
│                                                │
│  ┌── Rust 核心（主进程，src-tauri/）─────────┐  │
│  │  · 命令注册中心（lib.rs）                 │  │
│  │  · 文件系统 / 搜索 / AI / 博客 / 插件管理   │  │
│  │  · 所有"碰磁盘、碰网络、起进程"的事        │  │
│  └──────────────────────────────────────────┘  │
│            ▲ invoke（IPC 桥）                   │
│            │  JSON 参数/返回值                  │
│  ┌── WebView 前端（渲染进程，src/）─────────┐  │
│  │  · Vue 3 + TypeScript                  │  │
│  │  · 状态层（vault/plugins/checklists…）     │  │
│  │  · 视图层（笔记/插件/工具/清单/博客…）      │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
                │
                ▼ 读写
        ┌────────────────┐
        │  vault 工作区   │  ← 用户的"数据主权"文件夹
        └────────────────┘
```

**三个核心认知**：

1. **前端 ≠ 后端**：前端框架只负责界面和状态；所有文件读写、网络请求、子进程都在 Rust 里做，前端通过 `invoke("命令名", 参数)` 调用。好处：安全（前端拿不到任意路径权限）、性能（重活不卡 UI）。
2. **"数据永远是用户的"**：整个应用不建私有数据库，所有内容都是 `vault/` 文件夹里的普通文件（Markdown / JSON）。关掉应用、删掉应用，数据还在，随时可以用 git/网盘/手动复制备份。
3. **命令即接口**：Rust 侧每个 `#[tauri::command]` 函数就是一个可被前端调用的 API；前后端之间的"接口文档"就是这些命令的签名。

## 2. 前端技术栈（src/）

### 2.1 Vue 3
- **组件**：`.vue` 单文件组件（`<script setup>` + 模板 + `<style>`）；视图组件（SettingsView/PluginsView…）→ 组合组件（TopBar/Sidebar…）。
- **响应式三件套**：
  - `ref / reactive`：本地状态（如编辑器是否忙碌、搜索词）
  - `watch / watchEffect`：副作用（挂载时加载数据、监听键盘事件；`onMounted`/`onBeforeUnmount` 对应生命周期）
  - `computed`：派生状态（缓存计算，依赖变化自动重算）
- **模块级单例 store**（本项目状态管理的核心，替代原 React Context）：
  ```ts
  // src/core/vault.ts —— 整个"工作区"状态的唯一来源
  const state = reactive({ path: null, files: [], ... });
  export function useVault() { return { state, openFile, save, ... }; }
  ```
  所有笔记相关状态（路径、文件树、当前文件、内容、脏标记）集中在一个模块里，任何组件 `useVault()` 就能读写。项目里有 3 个这样的 store：`vault / plugins / navigation`。
- **为什么用响应式代理而不是手动状态**：读 `reactive` 对象永远是当前值——原 React 版大量 `stateRef`/`useCallback` 闭包过期防护被天然消除；状态变化时只有依赖它的组件/计算属性重渲染。

### 2.2 TypeScript
- 给 JavaScript 加类型：`interface VaultContextValue`、`type ViewId = "notes" | "plugins" | ...`。
- 项目里的典型用法：
  - 前后端数据类型对齐（`FileEntry`、`SearchHit` 在 `api.ts` 里声明，与 Rust 的 `serde` 结构体字段一一对应）
  - 字符串字面量联合类型做"枚举"（如 `PluginInfo.status: "ready" | "stopped" | "error"`）
  - `pnpm build` 会先跑 `vue-tsc` 做类型检查（含 `.vue` 模板），等于给前端上了一道"编译期防线"。

### 2.3 Vite（构建工具）
- 开发时：`pnpm dev` 起本地服务器（端口 1420），改代码即时热更新（HMR）。
- 构建时：`pnpm build` → `vue-tsc`（类型检查）→ `vite build`（打包成 `dist/`）。
- 本项目用 **`defineAsyncComponent` 懒加载低频视图**（设置页/插件页独立 chunk，首屏只加载外壳）：`SettingsView`/`PluginsView` 按需加载；不设 `manualChunks`——Tauri 桌面应用整包更新、无 HTTP 缓存场景，JS 分包没有收益。

### 2.4 md-editor-v3（Markdown 编辑器，Vue 3 生态）
- **编辑模式**：左侧 Markdown 源码 + 右侧实时预览（分屏）；工具栏/主题/语言可配置，代码高亮与 KaTeX 数学公式内置（全部打进插件 UI 产物，离线可用）。
- 本项目对 md-editor-v3 的定制（`core-plugins/notes/ui/NoteEditor.vue`）：
  - 按需工具栏（撤销/重做、标题/加粗/斜体/删除线、列表/任务、引用/代码/链接/表格）
  - 自定义 AI 摘要按钮（`defToolbars`）：选中文本 → 调 core-ai → 以引用块替换选区
  - 主题跟随（宿主切换亮/暗时传 `theme`），`Ctrl+S` 触发保存
- 注：编辑器只存在于 **core-notes 插件自带前端**（`ui/NoteEditor.vue`）；宿主本身不引入任何编辑器库。

## 3. 后端技术栈（src-tauri/）

### 3.1 Rust（语言本身）
项目用到的最核心语法：
- **所有权 / 借用**：`&self`（只读借用）、`&mut self`（可变借用）、`move` 闭包。典型例子：`PluginManager` 被 `Mutex` 包住，命令里 `m.lock()` 拿到可变引用才能改。
- **Result / Option**：Rust 没有异常，函数返回 `Result<T, E>` 或 `Option<T>`；命令签名 `-> Result<Vec<PluginInfo>, String>` 里的 `Err` 会直接变成前端 `invoke` 抛出的错误。
- **`?` 运算符**：`std::fs::read_to_string(&p).map_err(|e| ...)?`——出错就提前返回。
- **async**：`async fn` 命令不会阻塞 Tauri 主线程，重活（读大文件、网络请求）不卡 UI。
- **trait**：`Serialize`（序列化）、`Default`、`Drop`（如 `ProcessPlugin` 的 Drop 实现进程清理）。

### 3.2 Tauri 2（应用框架）
- **命令系统（IPC）**：Rust `#[tauri::command]` + `.invoke_handler(tauri::generate_handler![...])` 注册；前端 `invoke("fs_list", { vault })` 调用。参数和返回值自动走 JSON 序列化。
- **State 管理**：`app.manage(Mutex::new(PluginManager::default()))` 注册全局状态，命令里 `State<'_, Mutex<PluginManager>>` 取用。用 `Mutex` 是因为命令可能是并发的，需要互斥。
- **能力系统（capabilities）**：`src-tauri/capabilities/default.json` 声明窗口能调哪些插件能力（如 `core:default`、`dialog:default`、`opener:default`）。这是 Tauri 2 的安全边界——前端默认不能随便调系统能力。
- **事件（Event）**：Rust 侧 `app.emit("事件名", data)` → 前端 `listen("事件名", cb)`。用于跨窗口/异步通知（后续浮窗清单的双窗同步就用它）。
- **多窗口**：`WebviewWindowBuilder` 或 tauri.conf.json 的 `windows[]`（浮窗方案的基础）。
- **开发调试**：`additionalBrowserArgs: "--remote-debugging-port=9226"` 可让 WebView2 暴露 CDP 端口，用脚本驱动真实窗口做 E2E（见第 5 节）。

### 3.3 序列化与文件
- **serde / serde_json**：Rust 结构体 ⇄ JSON。
  ```rust
  #[derive(Serialize)]
  #[serde(rename_all = "camelCase")]  // Rust 的 snake_case → 前端 camelCase
  pub struct FileEntry { pub name: String, pub path: String, pub is_dir: bool }
  ```
  `rename_all = "camelCase"` 是 Rust/JS 命名风格差异的常见解法。
- **路径安全（core/path.rs）**：所有"用户传入的相对路径"都要过 `resolve_safe`：
  - 拒绝空、`.`、`..`、绝对路径、盘符前缀
  - 拼出绝对路径后校验父目录 == vault 根（防 `../` 越界）
  - 这是"纯文件应用"最重要的安全防线。

### 3.4 插件系统（M2 里程碑的核心，阶段 0 起三种运行时）
- 三种运行时：
  - **webview 插件**（JS）：前端读取入口 JS，Blob URL `<script>` 注入求值（打包版 CSP `script-src 'self' blob:` 拦截 `new Function`），插件通过 `api.app.registerCommand` 注册命令到内存注册表。是"尽力而为"的沙箱——只给受限 api 对象（app/fs/events/log），不隔离 window 访问。
  - **process 插件**（Python 等）：Rust 用 `std::process::Command` 启动子进程，通过 **JSON-RPC 2.0 over stdio（NDJSON）** 通信——每行一个 JSON，`init` 握手返回插件声明的命令列表，之后按 id 调命令；崩溃自动重启（≤3 次/60s）、stdin 写超时回收挂死进程。
  - **native 插件**（核心，cdylib）：宿主进程内 FFI，见 §3.6——最高性能，信任代码。
- **清单（plugin.json）**：`{ id, name, version, runtime, entry|command, permissions, config, searchProvider, nav }`——`searchProvider: true` 声明"搜索提供者"（实现 `search.provide {query, limit?} -> [{path, title, snippet}]`，启用后自动进入全局搜索）；`nav` 声明侧边栏入口（启用时并入导航，禁用即消失）。权限字段决定外部插件能否调用核心 API（fs 读写、日志）。
- **生命周期**：发现（扫描全局目录 `%APPDATA%/com.toolbox.desktop/plugins/` 与 `_core/` 子目录；插件是工具不属于某个工作区；旧版工作区 `plugins/` 自动迁移并清理）→ 启用（持久化到同目录 `plugins.json`，全局生效）→ 启动/加载 → 调用（`plugin_call` 统一路由）→ 崩溃处理（process 自动重启；native catch_unwind 隔离）→ 禁用/卸载（核心插件不可卸载）。
- **事件桥**：插件发 **Notification**（`{"method": "进度事件", "params": {...}}`，无 id）→ read_loop 解析为 `Incoming::Event` → ProcessPlugin 经**纯 mpsc 事件总线**（`plugins/events.rs`，不接触 tauri 类型）→ 转发线程 `app.emit("plugin-event")` → 前端插件页事件日志。native 插件经 `TbHostApi::emit_event` 汇入同一事件桥。**设计约束**：ProcessPlugin 曾因持有 `AppHandle` 触发测试二进制加载崩溃（0xC0000139），改为只持标准库 `Sender` 彻底规避——这是"避免在数据对象里塞框架类型"的教训。

### 3.5 网络与服务器
- **reqwest（blocking + rustls）**：AI 对话的 HTTP 客户端。用 `OnceLock` 缓存共享 client（连接复用，避免每次新建）。
- **reqwest 流式（stream feature）**：`ai_chat_stream` 用 async client 发 `"stream": true`，把响应按 **SSE** 逐块解析——`data: {"choices":[{"delta":{"content":"..."}}]}` 取增量，经 `ai-chunk` 事件推给前端（打字机）。SSE 行可能跨 TCP 块，用缓冲按 `\n` 切行；`data: [DONE]`、`: keep-alive` 注释行、空行都跳过。测试：内存字节流（半行跨块）+ 本地 mock HTTP 服务器端到端。
- **tiny_http**：博客预览的本地静态服务器（随机端口），返回渲染好的 HTML。
- **pulldown-cmark**：Rust 的 Markdown 解析器，博客生成时把 Markdown 渲染成 HTML（与前端 md-editor-v3 的预览各管一摊）。

### 3.6 核心插件 cdylib（阶段 0–2：C ABI + libloading，6 个插件）
- **动机**：核心功能（笔记/待办/清单/项目/博客/AI，6 个插件）既要有"插件形态"（可启用/禁用/热重载/被替换），又要**最高性能**——进程插件（JSON-RPC over stdio）每次调用毫秒级，对高频数据操作不可接受。cdylib 方案：插件编译为动态库（Windows .dll），宿主用 **libloading** 加载，经 **C ABI（extern "C"）** 直接函数调用——FFI + JSON 序列化微秒级，接近进程内调用。
- **五符号契约（tb-sdk 定义，`tb_plugin!` 宏生成样板）**：
  ```
  tb_abi_version() -> u32                 // ABI 协商，不匹配拒绝加载
  tb_create(config_json, *TbHostApi) -> handle   // 配置 JSON（含 vault 路径）+ 宿主服务表
  tb_call(handle, method, params_json) -> *char   // 统一返回 {"ok":bool,"result"|"error"}
  tb_free_string(s)                       // 宿主释放 tb_call 返回值
  tb_destroy(handle)                      // 销毁实例
  ```
- **TbHostApi（宿主回灌）**：函数指针表 `{ abi_version, ctx, emit_event, log, open_path }`——`ctx` 是宿主分配的上下文指针（当前 = 插件 id 字符串），回调的 ctx 参数即它，**插件只透传、不解引用**（早期版本忘了传 ctx，插件回调时空指针解引用直接崩了宿主，教训：跨 FFI 的所有指针都必须在契约里明确所有权）。`emit_event` 转发为前端 `plugin-event`（与进程插件共用事件桥）；`open_path` 用系统默认应用打开路径（项目插件用）。
- **panic 隔离**：`tb_call` 内 `catch_unwind`，插件 panic 返回错误 JSON 而不是崩宿主；但**段错误类崩溃仍会带走宿主**——核心插件是信任代码（随应用分发），与外部插件的权限门控不同。
- **默认启用**：核心插件（native）默认启用，显式禁用记入 `plugins.json` 的 `disabled` 数组；外部插件仍按 `enabled` 集合。`load_state` 兼容旧格式（按 vault 分键 map / 仅 enabled 数组）。**搜索/备份曾是 `system` 锁定插件，已按用户决定迁回宿主本体**（见 §3.6 末），`system` 标记字段保留但当前无系统插件实例。
- **加载/释放**：`NativePlugin { _lib, handle, ... }`——`Drop` 顺序 = 先 `tb_destroy` 再释放 `lib`（Windows 上 DLL 释放后文件才可覆盖）；启用/禁用/热重载 = load/drop。
- **workspace**：根 `Cargo.toml` 声明 members（`src-tauri` 宿主 + `tb-sdk` SDK + `core-plugins/*` 6 个插件）；插件 crate 只依赖 tb-sdk + 通用库，**不依赖 tauri**——接口干净，未来第三方也能写核心级插件。宿主 core/ 含 vault + path + **search（全文搜索）+ backup（自动备份）**（框架 + 系统级横切能力）。
- **部署**：`pnpm build:core`（debug → %APPDATA%）供 dev；`pnpm build:core:release`（release DLL → `src-tauri/resources/_core/`）打进安装包（`bundle.resources`）；打包版启动时 `ensure_core_plugins` 从 `resource_dir/_core` 清空后整体复制到 `%APPDATA%/.../plugins/_core`（随应用分发，与应用版本一致）。
- **统一路由**：`plugin_call(id, command, args)` 分发三种运行时（native → FFI；process → JSON-RPC；webview → 前端注册表），api.ts 全部透明转发。
- **插件自带前端（组件模式）**：manifest `ui.entry` 指向插件目录的自包含 JS（`ui/index.js`，由 `core-plugins/<id>/ui/index.ts` 用 Vite lib 模式构建为 IIFE，**Vue 3 打进产物**）。宿主 `PluginUiView`：`plugins_read_file` 读入口 → Blob `<script>` 注入 → 插件注册 `window.__TB_PLUGIN_UI__[id].mount(el, api)` → 宿主把 api 桥注入，插件用 `createApp(App, { api }).mount(el)` 挂载（宿主界面内直接渲染，非 iframe）。`plugins_read_file` 同时支持普通插件目录与 `_core/<id>`（核心插件）。**6 个核心插件全部自带前端**（博客/项目/笔记/清单/AI/待办浮窗）。笔记插件编辑器为 **md-editor-v3**（Vue 3 生态，全部打进产物，离线可用）。
- **统一插件运行时（pluginRuntime.ts）**：webview 插件与核心插件自带前端共用同一套加载机制——`injectPluginScript(code)`（Blob URL `<script>` 注入，CSP `script-src blob:` 允许，返回清理函数）与 `buildBridgeApi(pluginId, getVault, opts?)`（统一 api 桥：`call(command, args?, targetPluginId?)` → `plugin_call`，args 缺省 `{}` 防 invoke 丢参；`on(event, cb, targetPluginId?)` → 订阅 `plugin-event`（可跨插件订阅）；`context.vault` + 宿主快照扩展字段（activePath/activeContent）；`nav`（主窗口：`go/openNote/openChecklist/openRecord` 跨视图跳转）；`host.search`（主窗口：调宿主内嵌全文搜索，搜索迁回本体后插件界面仍可复用）。**webview 插件的 api 也因此获得 `call`/`on`/`context`**（可跨插件调用、订阅事件），与核心插件自带前端能力对齐——两种插件写一个 API 契约。插件界面内**不能 import 宿主模块**（独立构建）：图标内联、数据全部经桥、样式复用宿主全局 CSS（CSS 变量随主题自适应）；`nav.openNote` 经 `tb:open-note` 同 document 事件 + 挂载期标记把"打开哪篇笔记"传给插件笔记界面；笔记插件 UI 打开文件后经 `tb:vault-active` 回写宿主 vault（AI 预设等读取当前笔记）。
- **搜索/备份迁回本体（用户决策）**：搜索（SQLite FTS5 索引 + 搜索提供者聚合）与备份（快照/配置/插件存档/恢复 + 60s 后台线程）原本下沉为 `system` 锁定的核心插件；因它们是系统级横切能力而非可替换业务功能，按用户要求迁回宿主框架——`src-tauri/src/core/search.rs`（含 6 测试）+ `core/backup.rs`（含 3 测试），宿主命令 `search_all` / `backup_*` 直调，`search_all` 仍聚合启用插件的 `search.provide`（当前无提供者插件，机制保留）；前端 api.ts 备份段改宿主 invoke，插件界面经统一桥 `host.search` 复用搜索；插件数 9 → 7。**记录/数据工具按用户决定移除**（插件数 7 → 6，core/records.tsx + RecordsView + core-plugins/records 删除）。
- **侧边栏动态化 + 全配置（navPrefs v2）**：插件 manifest 的 `nav` 声明侧边栏入口（id/label/icon/group/view），启用即并入导航、禁用即消失。**导航栏完全用户可配置**：`toolbox.nav`（v2）存 `{ groups, order, meta }`——分组（内置 work/system + 用户自定义 + 插件动态组 dyn:）、每组的项顺序（插件项可任意跨组移动）、项元数据覆盖（标签/图标/隐藏）。`normalizeNav(cfg, defs)` 以当前项定义（静态 + 插件 nav）为底做归一化：内置组常驻、自定义组可改名/删除（组内项回默认组）、settings 强制可见、**失效项（插件禁用）保留在配置里**（渲染时忽略，重启用后回到用户位置）、新项自动补入默认组；App 持有归一化结果并持久化（自愈）。旧版 v1（order by label + hidden）自动迁移。

> 版本历史（git2/libgit2）已按用户决定整体移除——备份承担数据回滚职责（见 §3.5 备份恢复）。git2 相关依赖、自动提交线程、历史视图全部删除。

## 4. 核心概念（项目里的"黑话"）

### 4.1 Vault（工作区）
- **来源**：Obsidian 的术语，指"一个文件夹 = 一个知识库"。
- **本项目含义**：用户选择的任意文件夹，应用内所有数据（笔记/清单/博客/项目）都放里面；**插件与配置在应用目录，不在 vault**：
  ```
  vault/
  ├── notes/            # 笔记（Markdown，可子文件夹）
  ├── projects/         # 项目文件（+ archive/）
  ├── data/             # 清单 checklists/*.json、待办 todos/
  ├── site/             # 博客生成输出（可重建，不进备份）
  └── .toolbox/         # 备份 backups/、搜索索引 search-fts.sqlite
  ```
  应用目录：`%APPDATA%/com.toolbox.desktop/`（vault.json、ai.json、backup.json、plugins.json、float.json、plugins/ 外部插件、plugins/_core/ 核心插件）。
- **为什么设计成 vault**：数据与代码分离、可 git、可备份、可迁移；换电脑 = 复制文件夹。

### 4.2 纯文件优先（File-First）
- 一切皆文件，不做私有数据库。
- 优点：透明（用记事本就能看数据）、可版本管理、无锁定（不怕应用崩溃丢数据）。
- 代价：搜索/索引需要自己实现（当前是遍历+字符串匹配，大库可换 FTS——见 Backlog）。

### 4.3 Frontmatter（文件头元数据）
- Markdown 文件顶部的 `---` 包裹的 YAML 键值对：
  ```markdown
  ---
  title: 我的文章
  status: published
  tags: 工作, 随笔
  date: 2026-08-01
  ---
  正文……
  ```
- 项目用 `core/blogfm.ts`（前端）和 `core/blog.rs`（后端）各自解析一份（保持 CRLF 兼容）。
- 用途：博客发布（status/title/tags/date）、后续 AI 整理的素材。

### 4.4 双向链接与反链（Backlinks）
- 笔记里写 `[[其他笔记]]`（或清单里引用笔记路径）→ 系统能找出"谁引用了当前笔记"。
- 项目实现（core/checklists.tsx、Backlinks.tsx）：**精确路径匹配优先，无精确匹配时按 basename 兜底**（避免同名笔记误报）。
- 这是笔记软件"知识网络"的基础能力。

### 4.5 即时渲染（IR，见 2.4）

### 4.6 JSON-RPC 2.0 与 NDJSON
- **JSON-RPC 2.0**：远程调用协议，请求 `{ jsonrpc: "2.0", id, method, params }`，响应 `{ id, result|error }`。
- **NDJSON**（Newline-Delimited JSON）：每行一个 JSON 对象，天然适合流式 stdin/stdout 通信。
- 组合：Python 插件 = 一个循环"读一行 → 处理 → 写一行"，协议简单到任何语言都能实现（这就是"以后支持 Lua/Go"的落点）。

### 4.7 全文搜索（当前实现与局限）
- 当前：递归遍历 `notes/`，文件名匹配优先，正文用 `to_lowercase().contains()` 匹配，每文件限读 256KB。
- 局限：无分词、无索引、大库会慢。
- 演进方向（Backlog）：SQLite FTS5 或 tantivy 建索引，可增量更新。

### 4.8 SSG（静态站点生成）与 Zola 兼容
- 博客不是动态网站，而是"生成静态 HTML"：`blog_generate` 读取笔记 → 渲染 HTML → 输出到 `site/public/`，部署到任意静态托管即可。
- **Zola 兼容**：同时生成 `site/content/`（Markdown 源）+ `config.toml`，以后想换 Zola 框架直接消费这些源文件，不被锁定。

### 4.9 主题系统与设计令牌（Design Tokens）
- 设计令牌：把颜色/间距/字体等设计决策抽成 CSS 变量（`styles/tokens.css`），组件只引用变量不写死值。
- 主题 = 一套令牌覆盖：`ThemeDef { id, name, base, tokens }`，切换时设置 `data-theme` 属性 + 注入 `<style>` 覆盖变量。
- 内置 3 主题（亮/暗/暖）+ 自定义主题编辑器（实时预览，localStorage 持久化）。

### 4.10 本地优先（Local-First）与迁移
- 应用状态存 localStorage（布局偏好、主题），业务数据存文件，配置存 `%APPDATA%/com.toolbox.desktop/`（vault 路径、AI 配置）。
- 数据布局演进时写**自动迁移**（如笔记移到 notes/ 时把旧根目录 .md 搬进去），保证老用户升级不丢数据。

## 5. 开发与调试链路

- **?mock=1 浏览器模式**：不带 Tauri 也能在普通浏览器跑整个前端（用内置示例数据替换 IPC 调用），适合快速调 UI。实现：`isMock` 判断 + 各 Provider 里 mock 分支。
- **CDP（Chrome DevTools Protocol）**：WebView2 是 Chromium 内核，暴露 CDP 端口后可以用 WebSocket 发命令（`Runtime.evaluate` 执行 JS、`Page.captureScreenshot` 截图、`Emulation.setDeviceMetricsOverride` 模拟窗口尺寸）。
- **E2E 流程**（scripts/cdp-*.mjs）：临时在 tauri.conf.json 加 `--remote-debugging-port=9226` → `pnpm tauri dev` → CDP 脚本驱动真实窗口做断言。**这是"真实验证"的标准手段**——mock 测不到的（真实文件系统、真实进程、真实 WebView2）它都能测。
- **控制台转发**：前端 `console.error` 通过 `log_console` 命令转发到 Rust 终端，方便看前端报错。

## 6. 学习路线建议

1. **先读本文档第 1 节**建立架构图，再对照 `docs/操作手册.md` 的目录树走一遍代码。
2. **前端**：从 `src/App.tsx`（组件如何组织）→ `src/core/vault.tsx`（状态层怎么设计）→ 任意一个视图组件（如 NotesView）看"状态层 ↔ 视图层"如何联动。
3. **Rust**：从 `src-tauri/src/lib.rs`（命令注册全景）→ `core/notes.rs`（最简单的文件命令）→ `core/ai.rs`（async + HTTP）→ `plugins/`（最复杂：状态机 + 进程管理）。
4. **概念深化**：Vault/纯文件优先 → Frontmatter → 插件协议（JSON-RPC/NDJSON）→ 主题令牌 → SSG。
5. **动手实验**：`pnpm dev` + 浏览器开 `?mock=1` 改 UI；写一个自己的 webview 插件（照着 `plugins/text-stats/` 抄）；加一个 `#[tauri::command]` 并在 api.ts 里封装。
6. 遇到 Rust 报错先看 `cargo test` / `cargo check` 输出；前端类型错误看 `pnpm build`（tsc）输出。
