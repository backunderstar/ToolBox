## 0. 约束定义（关键，先对齐）

**"不额外增加过孔"** 解释为：**除输入文件中已存在的 pin 孔外，不得为连接某条 net 而新增任何过孔**。

由此推出**等价硬约束**：

> **每个网络整网单层（`same_net_same_layer = true`）。**

理由：
- 过孔只会在"**同一条 net 在布线中途换层**"时被逼出来（换层需要上下层间的金属孔）。
- 只要一条 net 的所有线段都落在**同一信号层**，其各 pin 就靠**该层上已有的 pin 孔**接入，net 内无需任何额外过孔。
- 因此**禁止"net 切层" ⟺ 不加额外过孔**。

**注意**：同一层的两条 net **交叉**不需要过孔（可在同一层内做平面绕行），它影响的是"好不好走"，**不违反零过孔**。所以过孔问题与"同层交叉/拥塞"是两个独立维度，本文分别处理。

**语义精化（沿用，但不作硬约束）**："同 net 线段尽量放一层"是**软偏好**，不是硬约束：
- 同 net 的多段**优先放同一层**（少过孔）；
- 但**放不了一层允许拆分**到不同层（不硬停、不强制整网）；
- 目标是"方便走线目标分层"——在同层优先的前提下保留灵活性。

## 1. 现状与差距

- **输入**：pin 引脚表（xlsx/lst）或 nets+pins → `io/wire_gen.rs` 合成**直线飞线**：
  - 2-pin → 1 段；3-pin → 外-远内 + 两内短段（可 2 段）；≥4-pin → Prim MST（多段）。
- **现状颗粒度**：`LayeringConfig.same_net_same_layer` 默认 **false**，`_make_units`（`layer_packing.rs`）按**线段**建 unit → 一条 net 的多段**可被分到不同层** → **会变相引入过孔**（违反约束）。
- **已实现的底座**：`_make_units` 在 `same_net_same_layer=true` 时**已支持整网单层**（按 `net_id` 归并所有段为 1 个 unit，允许层取并集）。即"整网单层"的算法路径**已存在，只差在配置/UI 上暴露**。

## 2. 里程碑 0 — "同 net 尽量同层"的软约束（最小化过孔）

**语义**：同 net 多段**尽量放同一层**（少过孔），但**放不了一层允许拆分**（不硬停）。即同 net 同层是**软偏好**，不是硬约束。

**做法（推荐：先整网分组、按需拆分，做成"两级决策"）**
1. **第一级 · net 级分配（主）**：以 **net 为粒度**做层分配。对每个 net，对每个候选层算一个代价
   `cost(net, layer) = 方向匹配度(`preferred_dir`) + 该层拥塞贡献 + λ·(是否拆分的潜在代价)`，
   用贪心（按"最难优先"）或最小费用/二分图匹配把**整网**先落到最优层。
   - 这一步已经**天然整网单层**（优先过孔最少），且把"方向贴合 + 拥塞"作为主驱动。
2. **第二级 · 段级拆分（兜底）**：仅当某 net 整网在第一级放不进任何一层时，才把**个别段**挪到别的层，
   并给该 net 记**一次拆分（=1 过孔）**。
3. **软代价**：目标函数加 `λ · Σ_nets max(0, 所在层数(net) − 1)`（或净跨层边界数）。`λ=0` 完全按段（现状），
   `λ→∞` 硬同层；取中间值兼顾"少过孔"与"好走线"。

**为何比"按段再尝试合并"更好**：先在 net 级做最优层分配，再对放不下的做段级拆分，收敛更可控、
代价更符合"少过孔"目标；也避免"整网放不下 → 只能整体挪"的一刀切。

**trade-off**：软偏好优于硬同层——既优先少过孔，又不因"某段受限"而拖垮整网/增加人工。需用 `λ` 扫描
找到"少过孔 vs 少硬冲突/少人工"的平衡。

**接入点**
- `config.rs`：新增 `same_net_via_penalty`（f64，默认如 1.0；0=按段，大=硬同层）、`net_layer_penalty`。
- `model.rs` / `_Unit`：增加所属 `net_id`（段拆分判定用）。
- `layer_packing.rs`：`_make_units` **两级**——先 `_make_net_units`（net 级），再对放不下的走 `_split_unit`；
  `_resolve_conflicts`/`_enforce_capacity` 增加"整网放不下→按段拆"分支并累计拆分代价（soft 容忍，不硬报错）。
- `optimizer.rs`：SA swap/move 判定加"拆分→via 代价"；`best` 用 `soft_crossings + λ·via_count` 选优。

## 3. 里程碑 1 — 模拟走线路径 + 可布性感知（**必要**，核心）

**为何必须**：pin 派生的直线段（2pin=1 段、3pin=2 段、≥4pin=MST 多段）里，**普遍存在过长的段**——一条从内 pad
到外探针的直线横跨整个板子，现实中**不可能按纯直线布线**（会与大量走线重叠、穿禁布区）。所以分层的几何判断
**必须用"模拟的实际走线路径"**，而非那条理想直线。

**思路（"全局布线 → 层分配"的标准做法，仅评估，不改输入、不做真实布线）**
1. **连接拓扑 = pin 派生段**：仍以输入 pin 数决定每 net 的"该连哪些 pin"（2pin/3pin/MST，`wire_gen.rs`）——
   **决定连通性**。
2. **几何路径 = 模拟走线路径**：为每条连接生成一条**可布路径**。路径生成做 **A/B 对比**：
   - **A（轻量，先做）**：沿层叠 `preferred_dir`（H/V）的**曼哈顿 L/Z 型** + 小 **dog-leg** 绕行避 keepout、避免过长。
   - **B（更贴近真实，备选）**：在**粗栅格上跑 A\*/迷宫布线**（带轻微拥塞代价），天然绕 keepout、更能反映真实可布性；代价是更慢。
3. **方向贴合**：路径形状应**随目标层方向（`preferred_dir`）而定**——H 层出 H 向、V 层出 V 向折线。当前是
   "先生成一条通用路径再用于各层"，会低估层向差异；建议对候选层按需生成**该层方向适配**的路径（配合性能护栏）。
4. 用该路径驱动**两道判定**：
   - **拥塞栅格**（`congestion.rs`）：栅格化模拟路径 → capacity 反映"曼哈顿/routing 密度"，而非必然相交的放射状直线密度。
   - **"同层可否共走"**（`conflict_classifier.rs`）：两条模拟路径若在曼哈顿下不交叠 → 真能共层；硬冲突数更贴近真实可布性。
5. **仍走"同 net 尽量同层(λ)"** → 满足"少过孔"目标。

**对"过长直线段"的说明**：模拟路径可能比直线更长，但它**沿 channel 走并绕开重叠**，能真实反映"层内好不好走、挤不挤"。这正是"分层后方便走通"需要的判断。

**收益**
- 分层结果"真正更可能走得通"（模型用的是可布路径）。
- 软/硬冲突更贴近 Allegro 实际布线难度，减少"看似分层却走不通"的局面。

**风险 / 约束**
- 估算路径 ≠ Allegro 实际布线，属**启发式**；需把路径生成器调稳（沿 preferred_dir、绕 keepout、长度尽量短），并保持与真实结果接近。
- 若输入全为 2-pin 单线，则"路径"仍是 pin→pin 的估算折线，冲突模型提升有限；收益主要在**多段/复杂 net** 与**拥塞**上。
- **路径生成是潜在瓶颈**（每 net 每候选层一条折线）。**性能护栏**：只对"候选层真正需判定冲突"的 net **懒生成**并**缓存**；
  用**低分辨率栅格做全局扫描**，冲突/精修时才在局部细粒度精算。

**接入点**
- 新增 `io/rout_estimate.rs`（或并入 `wire_gen.rs`）：`fn estimate_route(net, stack, zones, cfg) -> Polyline`。
- `congestion.rs`：`_rasterize` 改用折线段（多段栅格化），`_grid_geometry` 采集折线端点。
- `conflict_classifier.rs`：`pair_candidates` / `classify_pair` 换成折线对判定（分段直线相交 + 近距 + keepout）。
- `model.rs`：如需要，`Wire` 可加可选 `route: Vec<Point>`（不破坏现有字段语义）。

## 4. 里程碑 2 — 方案 C 的"无过孔版"（拥塞平滑代价 + 迭代整网重布线）

**适用性**：原方案 C 里"段级重布线 / 过孔最小化 / 依赖真实走线段"的部分在"零过孔、无真实走线"下**不适用**；
保留的是**拥塞代价 + 整网迭代优化**。

**做法**
1. **拥塞平滑代价**：把 `_enforce_capacity` 的"占用 > layer_capacity 才触发"硬开关，改为平滑代价
   `cost = Σ_{cell} (occupancy/supply)^k (k≥2)`，作为分层/精修的**软目标**，避免阈值附近抖动、避免"看似过容"。
2. **迭代整网 rip-up-and-reroute**：对高拥塞层上的**整网**整体搬到低拥塞/更匹配层；**必须整网移动**（保持单层），
   从而**不引入过孔** → 与零过孔约束自洽。
3. **路径级拥塞反馈**（完善点）：不是一次性算完所有 net 的拥塞，而是**每个 reroute 轮次根据当前分配重算拥塞**
   （`_enforce_capacity` 已有增量基础），让"挪一个 net"实时看到拥塞变化，收敛更准。
4. 收敛：迭代直到无整网可改善（或达到 `max_loop_iterations`）。

**收益**
- 摊平各层拥塞 → 更"容易走通"、减少硬冲突/需人工。
- 对有大量多段 net / 高容量利用率的板子鲁棒性更好。

**接入点**
- `layer_packing.rs`：`_enforce_capacity` 改平滑代价；新增 `_reroute_net(net, target_layer)`（整网迁移，不切层）。
- `optimizer.rs`：SA 代价加"轻微拥塞惩罚"（用 `layer_capacity` 当软约束），仍在整网颗粒度下 swap/move。
- `config.rs`：新增可选参数（如 `congestion_k`、`ripup_rounds`），默认关闭，避免改变现有结果。

## 5. 验证与指标（通用 + 走通率硬指标）

统一用真实数据 `cargo test --release -p tb-probe-rat-layer -- --ignored --nocapture`（应用 `hv` 预设 config），对比基线（方案 B 已交付）：
`elapsed / layer_count / 已分配 / 硬冲突 / 软冲突 / 需人工 / 各层占用率`。

**"少过孔"验收断言**（里程碑 0 起即生效）：
- 统计**被拆分（跨层）net 数**与**每 net 段层数分布**；在硬冲突/需人工**不劣化**的前提下，跨层 net 数**相对"按段独立分层"显著下降**。
- `same_net_via_penalty`(λ) 可调；报告输出 `split_nets` / `via_count` 标记，便于核对"尽量同层 vs 允许拆分"。

**新增 · 走通率硬指标（最该补，把"容易走通"量化）**：
- 分配完成后，用一条**廉价的 maze-routing / flood-fill**，在**该 net 被分配的那一层**按 `layer_capacity` 试走它，
  输出 **`routable_nets / total_nets`（走通率）** 与 **`routable_segments / total_segments`**。
- 这样"分层后容易走通"从模糊目标变成**可量化、可对比**的数字；A/B 一测便知。需要时把 keepout / `track_pitch`
  纳入该检查（走道宽度 = 走线 + clearance + 2×pitch），保真度更高。

| 里程碑 | 主要改动 | 工作量 | 预期收益 | 风险 |
|---|---|---|---|---|
| 0 软同 net 同层（两级） | net 级分配 + 段级兜底拆分，`λ` 调参 | 小 | 少过孔 + 保留灵活性 | 需扫描 `λ` 平衡 |
| 1 模拟走线路径 | 可布路径（L/Z 或 A\*）→ 拥塞/冲突/可布性判断 | 中 | 真正符合"过长直线不可布"、分层更易走通 | 启发式偏差、路径生成瓶颈（需懒生成+缓存） |
| 2 方案C无过孔版 | 平滑代价 + 路径级迭代整网 reroute | 中大 | 更稳、摊平拥塞、减少人工 | 需控制收敛 |
| （横切）走通率指标 | 每层 maze-routing 试走 → routable% | 小 | 把"走通"变可量化，A/B 验证 | 近似，非 Allegro 实际 |

## 6. 决策点

1. **段拓扑 = pin 派生**（2pin=1 段、3pin=2 段、≥4pin=MST）：这是连通性来源，**不改**。
2. **几何判断 = 模拟走线路径**（里程碑 1，确认为必要）：因存在**过长直线段、按直线不可布**。
3. **路径生成 A/B**（L/Z vs A\*）与 `λ`（同 net 尽量同层强度）都建议**先 A/B 再定**，避免过度拟合模拟而偏离真实可布性。
4. **两级决策（先 net 级、后段级）** 设为里程碑 0 的默认做法——比"按段再尽量合并"更贴近"少过孔"目标。
5. 落地顺序建议：**里程碑 0（net 级软同层 + 两级拆分）→ 里程碑 1（模拟路径判断 + 走通率指标）→（需更稳）里程碑 2**。
6. **走通率指标**建议先行（改动小、收益大）——先在方案 B 基线加上，作为后续所有改进的**对比基准**。
