# ToolBox 第三方插件开发指南

> 适用对象：想为 ToolBox 写插件的开发者（不要求读过宿主源码）。
> 三种运行时全覆盖：**webview（TS/JS，跑在界面内）**、**process（Python 等任意语言，独立子进程）**、
> **native（Rust 编译的 DLL，宿主进程内 FFI）**。
> 读完本文你能独立完成三种插件的开发、构建、打包、安装与调试。
>
> 仓库内三个可直接对照的完整示例：
> `plugins/text-stats`（webview）、`plugins/csv-tool` / `plugins/py-tools`（process）、
> `core-plugins/notes`（native + 自带前端，最完整的样板）。

---

## 0. 插件系统总览

### 0.1 三种运行时怎么选

| 维度 | webview（TS/JS） | process（Python 等） | native（Rust cdylib DLL） |
|---|---|---|---|
| 运行位置 | 宿主 WebView 界面内 | 独立子进程 | 宿主进程内（FFI，libloading） |
| 通信方式 | 前端 API 对象（同进程） | JSON-RPC over stdio（NDJSON） | C ABI 函数指针 |
| 性能 | 快（同进程） | 慢（进程间 IPC，毫秒级） | 最快（微秒级） |
| 界面能力 | ✅ 可注册命令 / 自带前端 | ❌ 无界面（数据/逻辑型） | ✅ 可带自带前端（React IIFE） |
| 第三方库 | npm 依赖在**构建时**打进单文件 | pip 包（vendored / venv，见 §3.5） | Cargo 依赖编译进 DLL |
| 语言要求 | 浏览器 JS/TS | 任意语言（实现协议即可） | Rust（用 tb-sdk） |
| 文件/系统能力 | 仅 `api.fs`（工作区内） | 核心 API（工作区内，权限门控） | 完整（自己用 `resolve_safe`） |
| 崩溃隔离 | 同窗口，报错不崩宿主 | 子进程崩溃自动重启（限次） | panic 经 catch_unwind 隔离 |

**决策建议**：
- 界面 + 轻逻辑 → **webview**（默认推荐，无需任何运行时）；
- 数据处理 / 调第三方库 / 任意语言（Node、PowerShell…）→ **process**；
- 性能敏感、需要完整文件/网络/系统能力、要"编译型工具" → **native（Rust DLL）**。

### 0.2 插件目录与部署

```
%APPDATA%\com.toolbox.desktop\plugins\        ← 插件安装根（全局，与工作区无关）
├── <插件id>\                                  ← 外部插件（webview / process）：一个插件一个目录
│   ├── plugin.json                            ← 清单（必填）
│   ├── main.js / main.py / ...                ← 入口（webview / process）
│   └── ui\                                    ← 可选：自带前端（构建产物，见 §2.3）
└── _core\                                     ← 原生插件容器（native）
    ├── core-notes\                            ← 随应用分发的核心插件（打包时部署，可卸载/恢复）
    └── <第三方DLL插件id>\                      ← UI 安装或手动放入的 DLL 插件（见 §4.6）
```

- **webview / process 外部插件**：把插件目录复制进 `plugins\` 即完成安装。插件页点"刷新"即可发现；
  目录增删/清单变化也会自动触发重新发现（无需重启应用）。
- **native（DLL）插件**：不能直接丢进 `plugins\`（宿主会拒绝加载，见 §0.4）。
  两种合法路径：① 插件页"安装 DLL 插件"（选择 zip 包或目录，自动部署到 `_core\<id>`）；
  ② 手动放进 `plugins\_core\<id>\`（dev 构建也保留手动放入的插件，不会清理）。
- **启用状态**存在 `%APPDATA%\com.toolbox.desktop\plugins.json`（`{enabled:[...]}`），与工作区无关；
  **分享/下载的 vault 不会自动执行其中的插件**。
- 随应用分发的 6 个核心插件（笔记/待办/清单/项目/博客/AI）默认启用、可禁用、可**真实卸载**
  （卸载后记入 `removed_core`，可从插件页一键恢复；开发模式 `pnpm build:core` 重新部署）。

### 0.3 清单（plugin.json）字段

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "version": "0.1.0",
  "description": "一句话说明",
  "runtime": "webview | process | native",
  "entry": "main.js",                 // webview 必填：入口 JS（相对插件目录）
  "command": ["python", "main.py"],   // process 必填：启动命令 argv；native 必填：DLL 文件名
  "permissions": ["fs:read:vault", "fs:write:vault", "log"],
  "config": {},
  "searchProvider": false,            // true = 实现 search.provide 命令，进入全局搜索（§5）
  "system": false,                    // true = 数据安全/横切能力，前端不可禁用（核心插件才用）
  "ui": { "entry": "ui/index.js" },   // 可选：自带前端（§2.3）
  "nav": [{ "id": "my", "label": "我的工具", "icon": "puzzle", "group": "工作区" }]
}
```

- **id 规则**：小写字母/数字开头，仅含小写字母/数字/`-`（`_` 仅内部目录用）；**必须等于目录名**。
- 已知权限：`fs:read:vault`（读工作区内文件）、`fs:write:vault`（写工作区内文件）、`log`（日志）。
  未知权限只警告不阻止加载；**process 插件调核心 API 时按此门控**（§3.3）。
- `nav` 里的 `view` 字段是宿主内置视图名，第三方插件**不写**（点击后自动路由到本插件的
  自带前端 `ui`，见 §2.3 的加载机制）。

### 0.4 安全模型与能力边界（重要）

- **webview / process**：外部插件可直接安装使用。核心能力经**权限声明 + 服务端校验**开放；
  所有带 `vault` 参数的命令都会校验"必须等于已配置的工作区"——插件**不可能**把文件作用域
  指向任意目录（读任意文件夹/写任意位置会被拒绝）。
- **native（DLL）**：DLL 被加载进宿主进程 = 完全控制。因此只允许出现在 `plugins\_core\` 容器下
  （`_core` 下的子目录才有资格加载，见 §4.1）。`plugins\` 根下直接放 `runtime: "native"` 的目录
  会被拒绝启动并报错。**第三方 DLL 插件的合法路径就是 UI 安装（落到 `_core`）或手动放入 `_core`**。
- 插件安装包解压带 zip-slip 防护（拒绝 `../` 越界路径），id 白名单校验（防路径穿越）。

### 0.5 开发环境与工作流

```bash
# 仓库根（本指南面向"独立开发"，也可不在仓库里开发）
pnpm sync:plugins          # 把仓库 plugins/ 下的外部插件同步到 %APPDATA%（开发时改代码后跑）
pnpm build-external-ui plugins/<id>   # 构建外部插件的自带前端（ui/index.tsx → ui/index.js）
pnpm tauri dev             # 启动应用（dev 终端可见插件日志）
```

> 不在仓库里开发也没关系：直接改 `%APPDATA%\com.toolbox.desktop\plugins\<id>\` 里的副本，
> 在插件页点"重载"（process/native）或刷新页面（webview 命令重载）即可生效。
> process 插件进程常驻：改 Python 代码后需要"重载"或重启应用。

## 2. webview 插件（TS/JS）详解

跑在宿主 WebView 界面内（浏览器 JS 引擎），**没有 Node 运行时**。两种形态可同时用：
命令注册式（无界面）与自带前端（有界面）。

### 2.1 命令注册式入口（main.js / main.ts）

入口文件顶层会收到一个全局 `api` 对象（宿主按插件独立注入，见 §2.2）。示例
`plugins/text-stats/main.js`：

```js
api.app.registerCommand({
  id: "analyze",            // 命令 id（插件内唯一）
  name: "统计文本",          // 展示名（插件页命令试用台可见）
  run: async (args) => {    // args 是调用方传入的 JSON 对象
    const text = typeof args?.text === "string" ? args.text : "";
    const trimmed = text.trim();
    return {
      chars: [...text].length,
      words: trimmed ? trimmed.split(/\s+/).length : 0,
      lines: text.length === 0 ? 0 : text.split("\n").length,
      paragraphs: trimmed ? trimmed.split(/\n\s*\n/).length : 0,
    };
  },
});
```

**用 TS 写入口**：源码写 `main.ts`，构建时打成单文件 `main.js`：

```bash
npx esbuild main.ts --bundle --outfile=main.js --format=iife
```

> 打包版 CSP 会拦截 `eval` / `new Function`——**不要**在入口里用它们；宿主加载用的是
> Blob URL `<script>` 注入（CSP `script-src blob:` 允许），入口必须是普通脚本文件。

### 2.2 api 对象全字段

入口顶层直接可用的 `api`（由宿主 `src/core/plugins.tsx` 构造；字段与"插件自带前端"的
统一桥一致，见 §2.3）：

| 成员 | 说明 |
|---|---|
| `api.app.registerCommand({id, name, run})` | 注册命令（本插件的命令在此声明） |
| `api.fs.readText(rel)` / `api.fs.writeText(rel, content)` | 读写**工作区内**文件（vault 相对路径，`/` 分隔；越界被拒） |
| `api.events.on(event, cb)` / `api.events.emit(event, data)` | 插件内事件（本插件各入口间互通） |
| `api.log(...args)` | 打日志（dev 终端可见，前缀 `[plugin:<id>]`） |
| `api.call(command, args?, targetPluginId?)` | **调用插件命令**：默认本插件；传 `targetPluginId` 跨插件调用 native/process 插件 |
| `api.on(event, cb, targetPluginId?)` | 订阅 `plugin-event`（默认本插件；跨插件传第三个参数），返回取消函数 |
| `api.context` | 宿主注入上下文：`{ vault: 当前工作区路径, activePath?, activeContent? }` 等 |

**跨插件调用示例**（webview 插件调用 process 插件的命令）：

```js
const r = await api.call("csv.convert", { csv: "a,b\n1,2", format: "json" }, "csv-tool");
```

**事件订阅示例**（订阅 py-tools 推送的 progress 事件）：

```js
const off = api.on("progress", (data) => console.log("进度:", data));
// 不再需要时 off() 取消
```

### 2.3 自带前端（组件模式，有界面的插件推荐）

插件目录放一份自包含的 React 产物，宿主把它挂载到自己的界面里（**非 iframe**，宿主全局
CSS/主题直接生效）。text-stats 插件就带前端；6 个核心插件全部用此模式。

```
<插件id>\
├── plugin.json          # 声明 "ui": { "entry": "ui/index.js" }
└── ui\
    ├── index.tsx        # 源码：React 组件（宿主注入 api 桥）
    ├── index.js         # 构建产物：自包含 IIFE（React 打进产物）
    └── style.css        # 可选：插件样式（Vite 提取）
```

**ui/index.tsx 骨架**：

```tsx
import React, { useState } from "react";
import { createRoot, type Root } from "react-dom/client";

/** 宿主注入的桥 API（只声明用到的方法即可，完整字段见 src/core/pluginRuntime.ts） */
interface PluginBridgeApi {
  pluginId: string;
  call: (command: string, args?: unknown, targetPluginId?: string) => Promise<unknown>;
  on: (event: string, cb: (data: unknown) => void, targetPluginId?: string) => () => void;
  context: { vault: string | null } & Record<string, unknown>;
  nav?: { go: (view: string) => void; openNote: (rel: string) => void };
  host?: { search: (query: string) => Promise<unknown[]> };
}

export function MyToolUi({ api }: { api: PluginBridgeApi }) {
  const [text, setText] = useState("");
  const run = async () => {
    // 例：调用 py-tools 的统计命令（跨插件）
    const r = (await api.call("pytext.stats", { text }, "py-tools")) as { words: number };
    setText(`词数: ${r.words}`);
  };
  // 复用宿主全局 CSS class（.card / .btn 等）即可随主题自适应
  return <div className="my-tool"><button className="btn" onClick={run}>统计</button></div>;
}

/** 自包含 IIFE 入口：注册到宿主注册表，宿主 PluginUiView 挂载时调用 */
declare global {
  interface Window {
    __TB_PLUGIN_UI__: Record<string, {
      mount(el: HTMLElement, api: PluginBridgeApi): void;
      unmount?(): void;
    }>;
  }
}
window.__TB_PLUGIN_UI__ = window.__TB_PLUGIN_UI__ || {};
window.__TB_PLUGIN_UI__["my-tool"] = {
  mount: (el, api) => {
    const root: Root = createRoot(el);
    root.render(<MyToolUi api={api} />);
    window.__TB_PLUGIN_UI__["my-tool"].unmount = () => root.unmount();
  },
};
```

**构建**（仓库内直接跑现成脚本）：

```bash
pnpm build-external-ui plugins/my-tool
```

脚本（`scripts/build-external-ui.mjs`）做三件事：Vite lib 模式打 IIFE（React 打进产物、
`process.env.NODE_ENV` 显式 define——否则运行时 `process is not defined`）、产物写回
`<插件目录>/ui/`（index.js + style.css）。不在仓库开发时照抄该脚本的内联 vite 配置即可。

**加载机制**：宿主 `PluginUiView` 经 `plugins_read_file` 读 `ui/index.js` → Blob URL `<script>`
注入（CSP 允许）→ 插件顶层注册 `window.__TB_PLUGIN_UI__[id]` → 宿主注入 api 桥并挂载到 React 树。
`nav` 声明了入口的插件，侧边栏点击即进入本界面；`api.nav.go(view)` 可跳回宿主其他视图。

### 2.4 npm 依赖与构建

WebView 里**没有 Node 运行时**（不能 `require('fs')`，不能运行时读 node_modules）。
npm 依赖必须**在构建时打进单文件**：

```bash
# 命令注册式入口
npx esbuild main.ts --bundle --outfile=main.js --format=iife
# 自带前端（React 自动打进产物）
pnpm build-external-ui plugins/<id>
```

- ✅ 纯 JS 库（dayjs、papaparse 等）→ bundle 进产物。
- ❌ Node 内置模块（fs/path/child_process）→ 不可用；文件能力用 `api.fs.readText/writeText`（限定工作区）。
- 需要完整 Node 生态 → 改 process 插件跑（`"command": ["node", "main.js"]`，见 §3.7）。

## 3. process 插件（Python 等任意语言）详解

独立子进程 + **JSON-RPC 2.0 over stdio（NDJSON：每行一个 JSON 对象）**。
`plugins/csv-tool` 是最小完整示例，`plugins/py-tools` 是进阶示例（第三方库 + 事件 + 搜索提供者）。

### 3.1 协议（完整形态）

```
宿主 → 插件   {"id": 1, "method": "init",  "params": {"apiVersion": 1, "pluginId": "csv-tool"}}
插件 → 宿主   {"id": 1, "result": {"commands": ["csv.convert", "csv.eventTest"]}}
宿主 → 插件   {"id": 2, "method": "call",  "params": {"command": "csv.convert", "args": {...}}}
插件 → 宿主   {"id": 2, "result": {...}}                     # 成功
插件 → 宿主   {"id": 2, "error": {"code": -32000, "message": "..."}}   # 失败
插件 → 宿主   {"method": "progress", "params": {...}}         # Notification：事件推送（无 id）
插件 → 宿主   {"id": 3, "method": "fs.readText", "params": {"path": "notes/a.md"}}  # 调用核心 API
宿主 → 插件   {"id": 3, "result": "文件内容"}
宿主 → 插件   {"method": "shutdown"}                          # 关闭信号（无 id）
```

要点：
- **启动**：`command[0]` 为可执行程序，`command[1..]` 为参数；**cwd = 插件目录**（脚本可用相对路径）。
- **生命周期**：spawn → `init` 握手（响应里的 `commands` 数组即插件声明的命令白名单，未声明的
  命令宿主拒绝调用）→ ready →（`call` / 事件 / 核心 API）* → `shutdown`。
- **健壮性**（宿主侧保证）：调用超时 30s（挂死自动终止进程树）、崩溃自动重启（60s 窗口内限 3 次）、
  单行 > 8MB 丢弃、非法 UTF-8 按 lossy 处理不误判退出、stderr 透传终端（当插件日志）。
- **UTF-8 强制**：Windows 下管道默认 ANSI 代码页（GBK），Python 必须 `reconfigure(encoding="utf-8")`，
  否则中文 JSON 会乱码/崩溃（csv-tool 的 main 里已示范）。

### 3.2 最小 main.py（照抄 csv-tool 结构）

```python
#!/usr/bin/env python3
"""JSON-RPC over stdio（NDJSON）插件。核心约定了 3 种入站消息与 2 种出站消息。"""
import json
import sys

def handle_request(msg):
    """处理宿主请求（init / call），返回带 id 的响应。"""
    mid = msg.get("id")
    method = msg.get("method", "")
    params = msg.get("params") or {}
    try:
        if method == "init":
            result = {"commands": ["demo.hello"]}          # 声明命令白名单
        elif method == "call":
            command = params.get("command", "")
            args = params.get("args") or {}
            if command == "demo.hello":
                result = {"text": "你好，%s！" % args.get("name", "世界")}
            else:
                raise ValueError("未知命令: %s" % command)
        else:
            raise ValueError("未知方法: %s" % method)
        return {"id": mid, "result": result}
    except Exception as e:                                  # noqa: BLE001
        return {"id": mid, "error": {"code": -32000, "message": str(e)}}

def notify(event, params):
    """向宿主推送事件（Notification，无 id）→ 前端 api.on(event) 收到。"""
    sys.stdout.write(json.dumps({"method": event, "params": params}, ensure_ascii=False) + "\n")
    sys.stdout.flush()

def call_core(method, params):
    """调用核心 API（fs.readText 等，按 plugin.json 的 permissions 放行）。
    注意：只能在处理宿主请求期间调用（宿主在该期间才会响应核心 API 请求）。"""
    sys.stdout.write(json.dumps({"id": 9000, "method": method, "params": params}, ensure_ascii=False) + "\n")
    sys.stdout.flush()
    msg = json.loads(sys.stdin.readline())
    if "error" in msg:
        raise ValueError(msg["error"].get("message", "核心 API 错误"))
    return msg.get("result")

def main():
    # Windows 管道强制 UTF-8（否则中文 JSON 乱码）
    for stream in (sys.stdin, sys.stdout):
        try:
            stream.reconfigure(encoding="utf-8")
        except (AttributeError, ValueError):
            pass
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        msg = json.loads(line)
        if msg.get("method") == "shutdown":                 # 宿主关闭信号：及时退出，不要挂起
            break
        if "id" in msg and "method" in msg:
            sys.stdout.write(json.dumps(handle_request(msg), ensure_ascii=False) + "\n")
            sys.stdout.flush()

if __name__ == "__main__":
    main()
```

配套 `plugin.json`：

```json
{
  "id": "demo-py",
  "name": "Python 示例",
  "version": "0.1.0",
  "runtime": "process",
  "command": ["python", "main.py"],
  "permissions": ["fs:read:vault", "log"],
  "config": {}
}
```

### 3.3 核心 API（按权限放行）

| 方法 | 所需权限 | 说明 |
|---|---|---|
| `fs.readText` | `fs:read:vault` | 读工作区内文件。参数 `{path}`：vault 相对路径（`/` 分隔）；`..`/绝对路径/盘符越界被拒 |
| `fs.writeText` | `fs:write:vault` | 写工作区内文件。参数 `{path, content}`；父目录自动创建 |
| `fs.listDir` | `fs:read:vault` | 目录枚举。参数 `{dir}`（空 = vault 根）；返回 `[{name, path, isDir, size, mtime}]`，`path` 为相对路径，`mtime` 为 UNIX 毫秒整数（按最近修改排序用），按 `path` 排序 |
| `log` | `log` | 日志。参数 `{message}` → dev 终端 `[plugin:<id>] ...` |

**任何语言**只要实现"读 stdin 一行 JSON、写 stdout 一行 JSON"即可成为插件
（Node / PowerShell / Go / …同理，见 §3.7）。

### 3.4 事件推送

插件在**处理命令期间**（或后台线程）向 stdout 写 Notification 行即可推送事件：

```python
notify("progress", {"percent": 50, "message": "处理中…"})
```

宿主收到后转发为前端 `plugin-event`（payload `{pluginId, event, data}`）；前端/其他插件用
`api.on("progress", cb)` 订阅（默认只收本插件事件，跨插件传第三个参数）。插件页有实时事件流展示。

### 3.5 第三方库放置（Python 四种方案按需选）

| 方案 | 目录布局 | 适用 |
|---|---|---|
| **A. 系统 Python + pip** | `pip install x`（装进系统 site-packages） | 最简；依赖用户机器有 Python 与包 |
| **B. 插件目录 vendored（推荐自带插件用）** | `<插件>/vendor/`，`pip install --target vendor <pkg>`；代码 `sys.path.insert(0, os.path.join(os.path.dirname(__file__), "vendor"))` | 插件自包含，卸载即净；py-tools 即此方案 |
| **C. 插件内 venv** | `<插件>/.venv/`，command 用 `.venv/Scripts/python.exe`（Windows） | 依赖隔离干净，但目录大、首次需安装 |
| **D. 自带执行器** | `<插件>/runtime/python.exe` + 依赖 | 用户机器无 Python 也能跑（python-build-standalone，约 30–60MB） |

> cwd = 插件目录，`Path(__file__).parent` 即可定位插件内任意资源（如读取同目录的数据文件）。

### 3.6 搜索提供者（searchProvider）

`plugin.json` 声明 `"searchProvider": true` 并实现 `search.provide` 命令，启用后自动进入
**全局搜索聚合**（宿主 `search_all`：宿主 FTS 命中 + 所有启用提供者的命中一起返回，
来源以 `source: <插件id>` 字段标记，前端展示徽章）。契约见 §5，完整示例见
`plugins/py-tools/main.py` 的 `search_provide`。

### 3.7 其他语言 / Node

**Node 当执行器**（想要完整 npm 生态 / fs / path）：

```json
{ "runtime": "process", "command": ["node", "main.js"], "permissions": ["fs:read:vault"] }
```

`node_modules` 放插件目录即可（cwd = 插件目录，Node 标准解析）。协议同 §3.1——写
`process.stdin` 逐行 `JSON.parse` + `process.stdout.write(JSON.stringify(...) + "\n")`。
关闭信号 `{"method":"shutdown"}` 到达时 `process.exit(0)`。

## 4. native 插件（Rust DLL）详解

native 插件 = 编译为 **cdylib（Windows .dll）** 的独立 Rust crate，宿主用 **libloading** 加载，
经 5 个 `extern "C"` 导出符号调用。性能定位：FFI 函数调用 + JSON 序列化（微秒级），
是三种运行时里最快的通道。仓库样板：`core-plugins/notes`（含自带前端，最完整）。

### 4.1 能力与安全边界

- DLL 加载进宿主进程 = 完全控制宿主。因此宿主只认 `plugins\_core\` 容器下的插件：
  `plugins\` 根下 `runtime: "native"` 的目录会被拒绝启动（提示"不在核心插件目录"）。
- 第三方 DLL 插件两条合法路径：
  1. **插件页「安装 DLL 插件」**（推荐）：选 zip 包或插件目录 → 校验（native + command 非空 +
     id 白名单 + zip-slip 防护）→ 部署到 `_core\<id>` → 默认启用并启动。见 §4.6。
  2. **手动放入** `%APPDATA%\com.toolbox.desktop\plugins\_core\<id>\`（plugin.json + DLL +
     可选 ui/）：应用会随目录快照变化自动发现。
- 命令调用：宿主 `plugin_call` / 前端 `api.call` 统一路由（native → FFI），与 process 插件
  对前端完全透明。

### 4.2 工程结构

```
my-dll-plugin/
├── Cargo.toml            # [lib] crate-type = ["cdylib"]；依赖 tb-sdk
├── src/
│   └── lib.rs            # 状态类型 + 命令分发 + tb_plugin! 宏（FFI 样板全自动）
└── ui/                   # 可选：自带前端（ui/index.tsx → ui/index.js，同 §2.3）
```

`Cargo.toml`：

```toml
[package]
name = "my-dll-plugin"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]          # 产出 Windows .dll

[dependencies]
# tb-sdk 是本仓库内的 SDK crate（C ABI 契约 + 宏 + 路径安全）。
# 独立开发时把仓库根下的 tb-sdk/ 目录拷进自己项目（或作为 workspace member），path 引用：
tb-sdk = { path = "../tb-sdk" }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

### 4.3 入口样板（tb_plugin! 宏生成全部 FFI 样板）

```rust
//! 插件 id: my-dll-plugin。命令经 plugin_call("my-dll-plugin", ...) 调用。
use serde_json::{json, Value};
use std::ffi::c_void;
use tb_sdk::{emit, tb_plugin, TbHostApi};

/// 插件状态：宿主在 tb_create 时注入配置 JSON（含 vault 路径与应用配置目录）。
pub struct DemoState {
    vault: String,
}

fn state_from_cfg(cfg: &Value) -> Result<DemoState, String> {
    let vault = cfg.get("vault").and_then(|v| v.as_str()).unwrap_or("").to_string();
    if vault.is_empty() { return Err("缺少 vault 配置".to_string()); }
    Ok(DemoState { vault })
}

/// 命令分发：method + params → 结果。写操作后可 emit 事件通知前端。
fn call(
    state: &mut DemoState,
    host: TbHostApi,
    ctx: *mut c_void,
    method: &str,
    params: Value,
) -> Result<Value, String> {
    let vault = state.vault.clone();
    let s = |k: &str| params.get(k).and_then(|v| v.as_str()).map(String::from);
    match method {
        "demo.hello" => {
            let name = s("name").unwrap_or_else(|| "世界".into());
            Ok(json!({ "text": format!("你好，{name}！（vault: {vault}）") }))
        }
        "demo.ping" => {
            // 写操作后发事件：前端 api.on("demo-ping") 收到 { text }
            emit(host, ctx, "demo-ping", json!({ "text": "pong" }));
            Ok(Value::Null)
        }
        _ => Err(format!("未知命令: {method}")),
    }
}

// 宏生成 5 个 #[no_mangle] extern "C" 符号 + panic 隔离（catch_unwind）
tb_plugin!(DemoState, state_from_cfg, call);
```

### 4.4 C ABI 契约与宿主服务表

宏生成的 5 个符号：

| 符号 | 作用 |
|---|---|
| `tb_abi_version() -> u32` | 版本协商（宿主校验 == 3，不匹配拒绝加载） |
| `tb_create(config_json, host) -> handle` | 建实例；`host` = 宿主服务表 `TbHostApi`；失败返回 null |
| `tb_call(handle, method, params) -> *mut c_char` | 调命令，返回统一 `{"ok":true,"result":...}` / `{"ok":false,"error":"..."}` JSON |
| `tb_free_string(s)` | 释放 tb_call 返回的字符串（**必须实现，宿主依赖它回收**） |
| `tb_destroy(handle)` | 销毁实例（Drop 状态）；**有后台线程必须在此收尾**（见 §4.7） |

**TbHostApi 服务表**（宿主回灌，`tb_create` 时传入；回调的 `ctx` 参数是宿主分配的插件
上下文，**插件只透传不解引用**）：

| 回调 | 作用 |
|---|---|
| `emit_event(ctx, event, data)` | 插件 → 前端事件（宿主转发为 `plugin-event`），返回 0 成功 |
| `log(ctx, level, msg)` | 日志（0=info 1=warn 2=error）→ dev 终端 `[plugin:log]` |
| `open_path(ctx, path)` | 用系统默认应用打开文件/文件夹（返回 0 成功） |

`tb-sdk` 提供便捷封装：`tb_sdk::emit(host, ctx, "ev", json)`、`tb_sdk::log(host, ctx, 0, "...")`、
`tb_sdk::now_iso()`（本地时间 `YYYY-MM-DD HH:MM:SS`）。

### 4.5 路径安全（必须）

```rust
use tb_sdk::resolve_safe;
// 拒绝 .. / 绝对路径 / 盘符前缀；规范化后复核防符号链接逃逸
let p = resolve_safe(&vault, rel)?;   // rel 用 / 分隔的 vault 相对路径
```

所有文件操作都必须经它——这是"为什么不会写坏数据"的根基（宿主 `core/path.rs` 同款逻辑）。

### 4.6 构建 DLL → 打包 → UI 安装（完整流程）

```bash
# 1. 构建 release DLL
cargo build --release -p my-dll-plugin
# 产物：target/release/my_dll_plugin.dll（Windows；crate name 的 - 变 _）

# 2. 组装插件目录（目录名 = 插件 id）
my-dll-plugin/
├── plugin.json          # runtime: "native", command: ["my_dll_plugin.dll"]
├── my_dll_plugin.dll
└── ui/                  # 可选：自带前端（同 §2.3）
```

`plugin.json`：

```json
{
  "id": "my-dll-plugin",
  "name": "我的 DLL 插件",
  "version": "0.1.0",
  "runtime": "native",
  "command": ["my_dll_plugin.dll"],
  "description": "Rust DLL 插件示例",
  "permissions": ["fs:read:vault", "fs:write:vault", "log"],
  "ui": { "entry": "ui/index.js" },
  "nav": [{ "id": "my-dll", "label": "我的 DLL", "icon": "puzzle", "group": "工作区" }]
}
```

```bash
# 3. 打 zip 包（包内结构：plugin.json 在根，或唯一子目录 <id>/plugin.json 均可）
#    PowerShell: Compress-Archive -Path my-dll-plugin -DestinationPath my-dll-plugin.zip

# 4. 应用内安装：插件页 →「安装 DLL 插件」→ 选 zip（或插件目录）→ 自动部署到 _core/<id> 并启用
```

**安装时宿主校验**：runtime 必须 native；`command` 非空；id 白名单（拒绝路径穿越）；
zip 解压带 zip-slip 防护（拒绝 `../` 越界条目）。重复安装需先卸载。
**卸载**：插件页卸载 → `_core\<id>` 目录物理删除（手动安装的 DLL 插件不可恢复，谨慎）。

### 4.7 后台线程与 Drop 收尾（重要）

**若插件开了后台线程（网络服务器、轮询、runtime），必须在 `tb_destroy` 时停掉并 join**，
否则宿主禁用/重载插件即 `FreeLibrary` 卸载 DLL 后，残留线程执行已卸载代码 → 宿主崩溃。
样板：把可停止句柄（`Arc<AtomicBool>` 标志 / `mpsc::Sender` / `Child`）存进 State，实现
`Drop` 收尾（参考 `core-plugins/blog` 的预览服务器与 `core-plugins/ai` 的做法）。

### 4.8 在仓库内开发核心插件（可选）

想给 ToolBox 项目贡献核心插件（随应用分发、打安装包时内置）时：

1. 建 `core-plugins/<name>/`（Cargo.toml + src/lib.rs + ui/），tb-sdk 用
   `path = "../../tb-sdk"`。
2. 根 `Cargo.toml` 的 `[workspace].members` 登记新 crate。
3. `scripts/build-core.mjs` 的 `PLUGINS` 数组登记 `{ id, name, description, dll, ui, nav }`。
4. `pnpm build:core` 全量构建（debug DLL + ui → `%APPDATA%/plugins/_core/<id>/`）；
   `pnpm build:core:release` 构建 release 资源（打包版随应用分发）。

## 5. 搜索提供者专题（search.provide 契约）

声明 `"searchProvider": true` 后，宿主 `search_all` 会在每次全局搜索时调用插件的
`search.provide` 命令并把命中并入结果（带 `source: <插件id>` 来源标记）。

**请求**：`{ "query": string, "limit": number }`（limit 由宿主传，当前为 20）。
**响应**：数组 `[{ "path": string, "title": string, "snippet": string }]`。
- `path`：vault 相对路径（供前端打开/定位）。
- `title`：条目标题（宿主把它映射为结果行 filename）。
- `snippet`：命中摘要（"为什么命中"），前端展示。

**建议**（py-tools 的 `search_provide` 已示范）：
- 用 `fs.listDir`（需要 `fs:read:vault` 权限）递归枚举 vault，而不是直接读文件系统——目录
  访问也受权限门控，保持一致。
- 命中结果按 `mtime`（fs.listDir 返回的 UNIX 毫秒）**降序**截取 limit 条——保证"最近修改的
  文件"排在前面（宿主对提供者结果不做排序）。
- 排除隐藏目录与宿主忽略目录（`.git`、`.toolbox`、`node_modules`、`target`、`site`），
  避免备份副本等噪音进搜索结果。

**注意**：宿主对提供者超时 30s；提供者命中过多会被前端与宿主 FTS 结果混排，保持克制（≤limit）。

## 6. 调试与常见问题

### 6.1 日志与调试手段

- **process / native**：stderr → dev 终端（`pnpm tauri dev` 窗口），`[plugin:log]` / `[plugin:<id>]` 前缀。
- **webview**：`console.log` → dev 终端（`[plugin:<id>]` 前缀）；入口加载失败会在插件页显示错误。
- 插件页有**实时事件流**（可观察事件推送）与**命令试用台**（填 JSON 调任意命令）。
- 插件目录改动：webview 刷新页面重载；process/native 在插件页点"重载"。

### 6.2 常见问题速查

| 现象 | 排查 |
|---|---|
| 插件页不出现 | 目录名 ≠ plugin.json 的 id；plugin.json 非法（页面显示解析错误）；忘了复制到 `%APPDATA%` 插件根 |
| 命令调用报"未注册" | webview：入口未 `registerCommand` 或入口加载失败（看插件页错误状态）；process：init 未声明该命令 |
| 权限报错 | 调 `fs.*` 需在 permissions 声明 `fs:read:vault` / `fs:write:vault` |
| native 插件拒绝启动 | 目录不在 `_core` 下（见 §4.1）；ABI 版本不匹配（需升级 tb-sdk 重编译）；DLL 缺符号（tb_create 等） |
| 插件挂死/超时 | 30s 超时会终止进程并提示；检查死循环 / 等待输入 / 不消费 stdin |
| 崩溃自动重启 | 60s 窗口内最多 3 次，之后标记错误；看 stderr |
| 中文乱码（process） | Windows 管道默认 GBK：`stdin/stdout.reconfigure(encoding="utf-8")` |
| 改前端不生效 | 自带前端需重新构建（`pnpm build-external-ui plugins/<id>`）+ 重载；**dev 运行中重建可能被 exe 锁挡住，先停 dev** |
| 事件收不到 | 事件经 `plugin-event` 总线；`api.on(event)` 默认过滤本插件 id，跨插件需传 targetPluginId |
| webview 入口报 `process is not defined` | 构建时未 define `process.env.NODE_ENV`（见 §2.3） |
