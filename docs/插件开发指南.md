# ToolBox 插件开发指南

> 三种运行时：**JS/TS（webview，界面内）**、**Python 等任意语言（process，子进程）**、
> **Rust（native，cdylib DLL，libloading 加载）**。读完本文你能独立写出三种插件，
> 并学会第三方库的放置位置与"内嵌执行器"方案。

---

## 0. 插件系统总览

### 0.1 三类运行时对比

| 维度 | webview（JS/TS） | process（Python 等） | native（Rust cdylib） |
|---|---|---|---|
| 运行位置 | 宿主 WebView 界面内 | 独立子进程 | 宿主进程内（FFI） |
| 通信 | 前端 API 对象（同进程） | JSON-RPC 2.0 over stdio（NDJSON） | C ABI 函数指针 |
| 性能 | 快（同进程） | 慢（进程间 IPC，毫秒级） | 最快（微秒级） |
| 界面能力 | ✅ 可注册命令/自带前端 | ❌ 无界面（数据/逻辑型） | 可带自带前端（React IIFE） |
| 第三方库 | npm 打包进单文件 | pip 包（见 §5） | Cargo 依赖编译进 DLL |
| 可用范围 | 外部插件 ✅ | 外部插件 ✅ | **仅随应用分发的核心插件**（见 0.4） |
| 典型用途 | 界面工具、文本处理 | 数据处理、AI 脚本、任意语言 | 性能敏感、文件/网络/系统能力 |

### 0.2 插件目录与部署

```
%APPDATA%\com.toolbox.desktop\plugins\        ← 外部插件安装根（全局，与工作区无关）
└── <插件id>\                                  ← 每个插件一个目录
    ├── plugin.json                            ← 清单（必填）
    ├── main.js / main.py / ...                ← 入口（webview/process）
    └── ui\                                    ← 可选：自带前端（React IIFE 产物）
```

- 把插件目录复制进 `plugins\` 即完成"安装"（插件页自动发现，无需重启——目录增删实时生效）。
- 核心插件在 `plugins\_core\<id>\` 子目录，随应用分发（`pnpm build:core` 部署），可启用/禁用/热重载、不可卸载。
- 启用状态存 `plugins.json`（同目录），与工作区无关；**分享/下载的 vault 不会自动执行其中的插件**。
- 旧版装在工作区 `plugins\` 里的插件首次打开会自动迁移到全局（复制后工作区目录进回收站）。

### 0.3 清单（plugin.json）字段

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "version": "0.1.0",
  "description": "一句话说明",
  "runtime": "webview | process | native",
  "entry": "main.js",              // webview 必填：入口 JS（相对插件目录）
  "command": ["python", "main.py"],// process 必填：启动命令 argv；native 为 DLL 文件名
  "permissions": ["fs:read:vault", "fs:write:vault", "log"],
  "config": {},
  "searchProvider": false,         // true = 实现 search.provide，进入全局搜索
  "system": false,                 // true = 数据安全/横切能力，前端不可禁用
  "ui": { "entry": "ui/index.js" },// 自带前端（组件模式，见 §2.3）
  "nav": [{ "id": "my", "label": "我的工具", "icon": "puzzle", "group": "工作区" }]
}
```

已知权限：`fs:read:vault`（读工作区内文件）、`fs:write:vault`（写工作区内文件）、
`log`（日志）。未知权限只警告不阻止加载。**id 规则**：小写字母/数字/连字符，且必须等于目录名。

### 0.4 安全模型（重要）

- **webview / process**：外部插件可用；插件**经权限声明 + 服务端校验**访问核心能力；
  所有带 `vault` 的命令会校验必须等于已配置的工作区（不能把路径指向任意目录）。
- **native**：DLL 直接加载进宿主进程 = 完全控制。**当前只允许 `plugins\_core\` 下的随应用分发
  核心插件**（第三方插件声明 native 会被拒绝启动）。想用 native 能力 → 以核心插件形式开发
  （合并进应用构建，或与本项目作者协商分发渠道）。

## 1. 通用开发流程

```bash
# 1. 建目录 + 写 plugin.json
mkdir %APPDATA%\com.toolbox.desktop\plugins\my-tool
# 2. 写入口文件（main.js / main.py / ...）
# 3. （可选）自带前端：ui\index.tsx
# 4. 启动应用 → 插件页应出现"my-tool" → 启用
# 5. 改代码后：插件页点"重载"（或重启应用）；目录增删自动发现
```

> 开发期可把插件目录建在仓库 `plugins\<id>\`，用脚本复制到 `%APPDATA%`（参考
> `scripts/` 下已有插件的部署方式）；也可以直接改 `%APPDATA%` 里的副本。

## 2. 方式 A：JS/TS 插件（webview）

跑在宿主 WebView 界面内（浏览器 JS 引擎），有两种形态，可同时用。

### 2.1 命令注册式（无界面，插件页"命令试用台"可调用）

`plugins\text-stats\main.js` 就是最小示例：

```js
// 入口顶层会收到全局 api 对象（按插件独立注入，键为 __TB_PLUGIN_API_<id>__）
api.app.registerCommand({
  id: "analyze",            // 命令 id（插件内唯一；调用方以命令 id 调用，如 "analyze"）
  name: "统计文本",          // 展示名（插件页命令试用台可见）
  run: async (args) => {    // run 接收调用方传入的 args
    const text = typeof args?.text === "string" ? args.text : "";
    return { chars: [...text].length, lines: text.split("\n").length };
  },
});
```

**api 对象**（由 `src/core/plugins.tsx` 的 buildApi 构造）：

| 成员 | 说明 |
|---|---|
| `app.registerCommand(cmd)` | 注册命令（`{id, name, run(args)=>result}`） |
| `fs.readText(rel)` / `fs.writeText(rel, content)` | 读写**工作区内**文件（vault 相对路径） |
| `events.on(event, cb)` / `events.emit(event, data)` | 插件内事件 |
| `log(...args)` | 打日志（终端可见） |
| `call(command, args?, targetPluginId?)` | **跨插件调用**（native → FFI / process → JSON-RPC） |
| `on(event, cb, targetPluginId?)` | 订阅 `plugin-event`（可跨插件），返回取消函数 |
| `context` | `{ vault: 当前工作区路径 }` 等宿主注入上下文 |

### 2.2 前端调用插件命令

命令注册后，插件页"命令试用台"（CommandTry，经 `plugins_invoke(id, command, args)`）
可以填 JSON 参数调用；也可被**其他插件**经 `api.call("analyze", { text: "..." })` 调用
（默认调本插件；指定第三个参数 `targetPluginId` 可跨插件）。宿主其他视图调用走
`plugin_call(id, command, args)`（Rust 统一路由，前端封装见 `src/core/api.ts` 的 `pluginCall`）。

### 2.3 自带前端（组件模式，推荐用于"有界面"的插件）

核心插件全部用这种方式（博客/项目/笔记/清单/AI/待办）。插件目录 = DLL/JS + 前端页面：

```
<插件id>\
├── plugin.json          # 声明 "ui": { "entry": "ui/index.js" }
└── ui\
    ├── index.tsx        # 源码：React 组件（宿主注入 api 桥）
    ├── index.js         # 构建产物：自包含 IIFE（React 打进产物）
    └── style.css        # 可选：插件样式（Vite 提取）
```

**ui/index.tsx 骨架**（照抄 `core-plugins/<id>/ui/index.tsx` 的样板）：

```tsx
import React, { useEffect, useState } from "react";
import { createRoot, type Root } from "react-dom/client";

/** 宿主注入的桥 API（只声明用到的方法即可） */
interface PluginBridgeApi {
  pluginId: string;
  call: (command: string, args?: unknown, targetPluginId?: string) => Promise<unknown>;
  on: (event: string, cb: (data: unknown) => void, targetPluginId?: string) => () => void;
  context: { vault: string | null } & Record<string, unknown>;
  nav?: { go: (view: string) => void };
  host?: { search: (query: string) => Promise<{ path: string; filename: string; snippet: string }[]> };
}

export function MyToolUi({ api }: { api: PluginBridgeApi }) {
  const [text, setText] = useState("");
  // 注意：webview 插件的命令注册（main.js 的 registerCommand）供插件页"命令试用台"
  // 调用；plugin_call 只分发 native/process（webview 请由前端调用，见 §0.1）。
  // 所以界面内要么直接写逻辑，要么用 api.call 调**其他** native/process 插件。
  const run = () => {
    // 例：调用 core-ai 的 AI 摘要（跨插件，targetPluginId 指定）
    void api.call("ai.chat", { messages: [...] }, "core-ai").then((r) => { /* 展示 */ });
  };
  return <div className="my-tool">{/* 复用宿主全局 CSS class 即可随主题自适应 */}</div>;
}

/** 自包含 IIFE 入口：注册到宿主注册表，宿主 PluginUiView 挂载时调用 */
declare global {
  interface Window { __TB_PLUGIN_UI__: Record<string, { mount(el: HTMLElement, api: PluginBridgeApi): void; unmount?(): void }>; }
}
window.__TB_PLUGIN_UI__ = window.__TB_PLUGIN_UI__ || {};
window.__TB_PLUGIN_UI__["my-tool"] = {
  mount: (el, api) => {
    const root: Root = createRoot(el);
    root.render(<MyToolUi api={api} />);
    window.__TB_PLUGIN_UI__["my-tool"].unmount = () => root.unmount();
  },
};
```

**构建**（参考 `scripts/build-core.mjs` 的 `buildPluginUi`）：Vite lib 模式打 IIFE，
React 打进产物（宿主与插件各一份 React 实例，互不干扰）；**必须显式 define
`process.env.NODE_ENV`**，否则运行时 `process is not defined`：

```bash
vite build --config <内联配置>  # lib: { entry: ui/index.tsx, formats: ["iife"] }
```

> **加载机制**：宿主 `PluginUiView` 经 `plugins_read_file` 读 `ui/index.js` →
> Blob URL `<script>` 注入（CSP `script-src blob:` 允许）→ 插件顶层注册
> `window.__TB_PLUGIN_UI__[id]` → 宿主注入 api 桥并挂载到 React 树（非 iframe，
> 宿主全局 CSS 直接生效）。

### 2.4 webview 插件的第三方库（npm 依赖）

WebView 里**没有 Node 运行时**（不能 require('fs')，也不能运行时读 node_modules）。
npm 依赖必须**在构建时打进单个 main.js / ui/index.js**：

```bash
# 用 esbuild 打包入口（含依赖）
npx esbuild main.tsx --bundle --outfile=main.js --format=iife
# 或 vite lib 模式（自带前端用，React 自动打进产物）
```

- ✅ 纯 JS 库（dayjs、papaparse 等）→ bundle 进产物，无放置问题
- ❌ Node 内置模块（fs/path）→ 不可用；需要文件能力用 `api.fs.readText/writeText`（限定工作区）
- 需要完整 Node 生态 → 见 §6.2（Node 当 process 插件跑）

## 3. 方式 B：Python 插件（process）

子进程 + **JSON-RPC 2.0 over stdio（NDJSON：每行一个 JSON 对象）**。
`plugins\csv-tool\` 是最小完整示例（CSV→JSON/TSV + 进度事件）。

### 3.1 协议

```
宿主 → 插件   {"id": 1, "method": "init",  "params": {"apiVersion": 1, "pluginId": "csv-tool"}}
插件 → 宿主   {"id": 1, "result": {"commands": ["csv.convert", "csv.eventTest"]}}
宿主 → 插件   {"id": 2, "method": "call",  "params": {"command": "csv.convert", "args": {...}}}
插件 → 宿主   {"id": 2, "result": {...}}                     # 或 {"id": 2, "error": {"code":-32000,"message":"..."}}
插件 → 宿主   {"method": "progress", "params": {...}}         # Notification：事件（无 id）
插件 → 宿主   {"id": 3, "method": "fs.readText", "params": {"path": "notes/a.md"}}   # 调用核心 API
宿主 → 插件   {"id": 3, "result": "文件内容"}
宿主 → 插件   {"method": "shutdown"}                          # 关闭信号
```

- **启动**：`Command::new(command[0]).args(command[1..])`，**cwd = 插件目录**（脚本可用相对路径）。
- **生命周期**：start → init 握手（声明命令）→ ready →（call / event / core API）* → shutdown。
- **健壮性**：调用超时 30s（挂死自动终止进程）、崩溃自动重启（窗口期内限 3 次）、协议版本协商、
  stderr 透传终端（当插件日志）。

### 3.2 最小插件 main.py（照抄 csv-tool 结构）

```python
#!/usr/bin/env python3
"""JSON-RPC over stdio（NDJSON）插件示例。
核心约定了 3 种入站消息与 2 种出站消息，实现如下主循环即可成为插件。
"""
import json
import sys


def handle_request(msg):
    """处理宿主请求（init / call），返回带 id 的响应。"""
    mid = msg.get("id")
    method = msg.get("method", "")
    params = msg.get("params") or {}
    try:
        if method == "init":
            result = {"commands": ["demo.hello"]}          # 声明命令列表
        elif method == "call":
            command = params.get("command", "")
            args = params.get("args") or {}
            if command == "demo.hello":
                result = {"text": "你好，%s！" % args.get("name", "世界")}
            else:
                raise ValueError("未知命令: %s" % command)
        else:
            raise ValueError("未知方法: %s" % method)
        return {"id": mid, "result": result}
    except Exception as e:                                  # noqa: BLE001
        return {"id": mid, "error": {"code": -32000, "message": str(e)}}


def notify(event, params):
    """向宿主推送事件（Notification，无 id）→ 前端 api.on(event) 收到。"""
    sys.stdout.write(json.dumps({"method": event, "params": params}, ensure_ascii=False) + "\n")
    sys.stdout.flush()


def call_core(method, params):
    """调用核心 API（fs.readText 等，按 permissions 放行）。"""
    sys.stdout.write(json.dumps({"id": 9000, "method": method, "params": params}) + "\n")
    sys.stdout.flush()
    return json.loads(sys.stdin.readline())


def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        msg = json.loads(line)
        if msg.get("method") == "shutdown":                 # 宿主关闭信号
            break
        if "id" in msg and "method" in msg:
            sys.stdout.write(json.dumps(handle_request(msg), ensure_ascii=False) + "\n")
            sys.stdout.flush()


if __name__ == "__main__":
    main()
```

配套 `plugin.json`：

```json
{
  "id": "demo-py",
  "name": "Python 示例",
  "version": "0.1.0",
  "runtime": "process",
  "command": ["python", "main.py"],
  "permissions": ["fs:read:vault", "log"],
  "config": {}
}
```

### 3.3 Python 插件的核心 API（按权限放行）

| 方法 | 所需权限 | 说明 |
|---|---|---|
| `fs.readText` | `fs:read:vault` | 读工作区内文件（`path` 为 vault 相对路径，`..` 等越界被拒绝） |
| `fs.writeText` | `fs:write:vault` | 写工作区内文件（原子写：临时文件 + rename） |
| `log` | `log` | 日志 |

**任何语言**只要实现"读 stdin 一行 JSON、写 stdout 一行 JSON"即可成为插件
（Node/PowerShell/Go…同理，见 §6）。

## 4. 方式 C：Rust 原生插件（native / libloading）

> "llb" = **libloading**：宿主用 `libloading` 加载 cdylib DLL，经 5 个 `extern "C"` 符号调用。
> **当前仅随应用分发的核心插件可用**（`plugins\_core\`，见 §0.4）；下面的流程
> 面向给 ToolBox 项目贡献核心插件，或参考它在 Rust 侧做高能力插件。

### 4.1 工程结构（照抄 `core-plugins/notes`）

```
core-plugins/<name>/
├── Cargo.toml            # [lib] crate-type = ["cdylib"]；依赖 tb-sdk（path）
└── src/
    ├── lib.rs            # 状态类型 + 命令分发 + tb_plugin! 宏（样板全自动）
    ├── fs.rs             # 业务逻辑（可拆分模块）
    └── ui/               # 可选：自带前端（React IIFE，同 §2.3）
```

`Cargo.toml` 关键点：

```toml
[lib]
crate-type = ["cdylib"]          # 产出 Windows .dll
[dependencies]
tb-sdk = { path = "../../tb-sdk" }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

### 4.2 入口样板（tb_plugin! 宏生成全部 FFI 样板）

```rust
//! 插件 id: core-demo。命令经 plugin_call("core-demo", ...) 调用。
use serde_json::{json, Value};
use std::ffi::c_void;
use tb_sdk::{emit, tb_plugin, TbHostApi};

/// 插件状态：由宿主在 tb_create 时注入配置（含 vault 路径与应用配置目录）。
pub struct DemoState {
    vault: String,
}

fn state_from_cfg(cfg: &Value) -> Result<DemoState, String> {
    let vault = cfg.get("vault").and_then(|v| v.as_str()).unwrap_or("").to_string();
    if vault.is_empty() { return Err("缺少 vault 配置".to_string()); }
    Ok(DemoState { vault })
}

/// 命令分发：method + params → 结果。写操作后可 emit 事件通知前端。
fn call(
    state: &mut DemoState,
    host: TbHostApi,
    ctx: *mut c_void,
    method: &str,
    params: Value,
) -> Result<Value, String> {
    let vault = state.vault.clone();
    let s = |k: &str| params.get(k).and_then(|v| v.as_str()).map(String::from);
    match method {
        "demo.hello" => {
            let name = s("name").unwrap_or_else(|| "世界".into());
            Ok(json!({ "text": format!("你好，{name}！（vault: {vault}）") }))
        }
        "demo.ping" => {
            // 写操作后发事件：前端 api.on("demo-ping") 收到 { text }
            emit(host, ctx, "demo-ping", json!({ "text": "pong" }));
            Ok(Value::Null)
        }
        _ => Err(format!("未知命令: {method}")),
    }
}

// 生成 5 个 extern "C" 符号 + panic 隔离（catch_unwind）
tb_plugin!(DemoState, state_from_cfg, call);
```

### 4.3 C ABI 契约（tb-sdk 定义）

| 符号 | 作用 |
|---|---|
| `tb_abi_version() -> u32` | 版本协商（不匹配拒绝加载） |
| `tb_create(config_json, host) -> handle` | 建实例；`host` = 宿主服务表 `TbHostApi` |
| `tb_call(handle, method, params) -> *mut c_char` | 调命令，返回统一 `{ok, result\|error}` JSON |
| `tb_free_string(s)` | 释放 tb_call 返回的字符串 |
| `tb_destroy(handle)` | 销毁实例（Drop 状态；若插件有后台线程，须在此停掉——见 §6.4） |

**TbHostApi 服务表**（宿主回灌给插件）：`emit_event`（插件→前端事件，转发为
`plugin-event`）、`log`（日志）、`open_path`（系统默认应用打开）。回调的 `ctx`
是宿主分配的插件上下文，**插件只透传不解引用**。

### 4.4 路径安全（tb-sdk 内置）

```rust
use tb_sdk::resolve_safe;   // 拒绝 .. / 绝对路径 / 盘符；规范化复核防符号链接逃逸
let p = resolve_safe(&vault, rel)?;   // rel 用 / 分隔的 vault 相对路径
```

所有文件操作都必须经它，这是"为什么不会写坏数据"的根基（宿主 `core/path.rs` 同款）。

### 4.5 构建与部署（核心插件）

```bash
pnpm build:core             # 全量：debug DLL + ui → %APPDATA%/plugins/_core/<id>/
# 或只构建：cargo build -p tb-demo
# 部署到 _core（外部插件不可用 native；核心插件由此分发）
```

Cargo workspace 在根 `Cargo.toml` 声明 members；`scripts/build-core.mjs` 的
`PLUGINS` 数组登记 id/dll/ui/nav，构建后写 plugin.json。

## 5. 第三方库的放置位置（专题）

### 5.1 Python：四种方案按需选

| 方案 | 目录布局 | 适用 |
|---|---|---|
| **A. 系统 Python + pip** | `pip install x`（装进系统 site-packages） | 最简；依赖用户机器有 Python 与包 |
| **B. 插件目录 vendored（推荐给自带插件用）** | `<插件>/vendor/`，`pip install --target vendor`；代码 `sys.path.insert(0, os.path.join(os.path.dirname(__file__), "vendor"))` | 插件自包含，卸载即净 |
| **C. 插件内 venv** | `<插件>/.venv/`，command 用 `.venv/Scripts/python.exe`（Windows） | 依赖隔离干净，但目录大、首次需 `pip install -r requirements.txt` |
| **D. 自带执行器** | `<插件>/runtime/python.exe` + 依赖（见 §6.1） | 完全脱离系统 Python |

> cwd = 插件目录，所以 `main.py` 里 `Path(__file__).parent` 即可定位插件内任意资源。

### 5.2 JS/TS（webview）：构建期打包

npm 依赖**不能运行时读取**（WebView 无 Node），必须在构建时 bundle 进单文件（§2.4）。

### 5.3 JS（process 模式，Node 当执行器）：node_modules 就在插件目录

`command: ["node", "main.js"]` + cwd = 插件目录 → Node 标准解析（`node_modules`
放插件目录下即可）。这是"想要完整 Node 生态（fs/path/npm 包）"的正解（§6.2）。

### 5.4 Rust（native）：Cargo 依赖编译进 DLL

crate 依赖在编译期解析，产物自包含（不需要运行时放置）。代价：依赖越大 DLL 越大。

## 6. 嵌入执行器方案（专题）

**结论：能。** 三种语言各自有"自带运行时"的路径，按场景选：

### 6.1 Python：内嵌独立 Python 发行版（python-build-standalone）

[python-build-standalone](https://github.com/astral-sh/python-build-standalone)
（uv 官方同源）提供解压即用的独立 Python（约 30–60MB）：

```
<插件>/runtime/
├── python.exe            # 独立解释器（不依赖系统 Python）
├── Lib/ python312.dll ...
└── requirements.txt      # 或预装好的 site-packages
```

- 安装：下载 `python-3.12.x-<platform>-install_only.tar.gz` → 解压到 `runtime/` →
  `pip install --target runtime/Lib/site-packages` 预装依赖（或首次运行自动装）。
- 清单：`"command": ["runtime/python/python.exe", "main.py"]`（cwd=插件目录，相对路径可解析）。
- 优点：用户机器无 Python 也能跑；依赖锁定；卸载插件即整体删除。
- 代价：体积大；首次部署耗时（可在插件首次启用时提示）。

### 6.2 JS：Node 当执行器（process 模式）

想要 npm 生态/文件系统 → 不跑 webview，改跑 process：

```json
{ "runtime": "process", "command": ["node", "main.js"], "permissions": ["fs:read:vault"] }
```

- 依赖 Node（或像 6.1 一样带 `runtime/node.exe` 进插件目录——Node 官方有独立二进制）。
- `node_modules` 放插件目录（§5.3）；能同时用 webview 自带前端做界面 + process 做逻辑，
  两者经 `api.call` / 事件互通（核心插件"笔记/AI"就是 native+前端 的组合模式）。
- 想要更强沙箱/去 Node 依赖 → 用 Rust 插件内嵌 QuickJS（`quick-js` crate）或 Deno core，
  属于进阶方案（体积与复杂度高，非必需）。

### 6.3 界面 JS（webview）：执行器天然内置

WebView 自带 V8/WebKit 引擎——**不需要嵌入任何执行器**。这也是默认推荐：
界面 + 轻逻辑直接写 webview 插件。

### 6.4 Rust：不需要执行器；注意线程回收

- 已编译产物，无解释器问题。
- **若插件开了后台线程（网络服务器、runtime、轮询），必须在 `tb_destroy` 时停掉并 join**，
  否则宿主禁用/重载插件即 FreeLibrary 卸载 DLL 后，残留线程执行已卸载代码 → 宿主崩溃。
  样板：把可停止句柄存进 State，实现 `Drop` 收尾（参考 `core-plugins/blog` 的预览服务器
  与 `core-plugins/ai` 的 runtime 移入实例的做法）。

## 7. 调试与常见问题

| 现象 | 排查 |
|---|---|
| 插件页不出现 | 目录名 ≠ plugin.json 的 id；plugin.json JSON 非法（页面显示解析错误）；忘了复制到 `%APPDATA%` 插件根 |
| 命令调用报"未注册" | webview：入口未 `api.app.registerCommand` 或入口加载失败（看插件页错误状态）；process：init 未声明该命令 |
| 权限报错 | 调 `fs.*` 需在 permissions 声明 `fs:read:vault` / `fs:write:vault` |
| 插件挂死/超时 | 30s 超时会终止进程并提示；检查是否有死循环/等待输入 |
| 崩溃自动重启 | 窗口期 60s 内最多 3 次，之后标记错误；看 stderr（dev 终端透传） |
| 改前端不生效 | 自带前端需重新构建（vite IIFE）+ 插件页重载；**dev 运行中重建会被 exe 锁挡住，先停 dev** |
| 事件收不到 | 事件经 `plugin-event` 总线；`api.on(event)` 默认过滤本插件 id，跨插件需传 targetPluginId |

**日志**：插件 stderr → dev 终端（`[plugin:log]` 前缀）；webview 插件 `console.log` 前缀
`[plugin:<id>]`。事件流可在插件页实时查看。
