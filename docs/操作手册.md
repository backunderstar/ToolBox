# ToolBox 操作手册

> 个人工具箱桌面应用 —— Rust 核心 + 多语言插件系统 + 主题系统。
> **教学基线（2026-08-29）**：宿主框架能力完整（工作区 / 宿主文件服务 / 全文搜索 /
> 自动备份 / 插件系统 / 主题 / 托盘 / 浮窗 / 打包分发），业务功能全部插件化；
> 核心插件 = 一个教学示例 **core-example**（照它学写新核心插件，教程见
> [核心插件示例教程.md](核心插件示例教程.md)）。笔记/清单/待办/项目/博客/AI 等
> 业务插件已移除（git 历史可查，按需重建为插件）。
> 当前可操作：插件系统（JS/Python/native 三类 + 界面安装 + 安装依赖）、全局搜索、
> 自动备份、主题、托盘与浮窗、打包发布。

## 1. 项目是什么

| 维度 | 内容 |
|---|---|
| 形态 | Windows 桌面应用（Tauri 2 打包，WebView2 渲染） |
| 核心语言 | Rust（文件服务、搜索、备份、插件管理、捆绑 Python 运行时） |
| 界面 | Vue 3 + TypeScript + Vite 8.2 |
| 数据 | 纯文件优先：vault 工作区内的普通文件（Markdown/JSON），可 git、可迁移 |
| 扩展 | 插件系统：JS（界面内）+ Python 等任意语言（子进程，捆绑运行时）+ Rust（cdylib DLL，宿主进程内 FFI） |

**核心架构一句话**：Rust 干"重活"（文件服务、搜索、备份、插件进程管理、捆绑 Python），WebView 干"好看"（界面、主题），两者通过 Tauri IPC（`invoke` 命令）通信。

```
┌─ WebView UI（Vue 3/TS）───────────────────┐
│  视图层：概览/插件/设置 + 插件 nav 动态路由（如示例插件） │
│  状态层：vault / plugins / nav 配置（导航全配置） │
│  主题引擎：ThemeDef + CSS 变量覆盖            │
└───────────────┬────────────────────────────┘
                │ IPC（invoke / log_console）
┌───────────────┴────────────────────────────┐
│  Rust 核心（Tauri 2）                        │
│  core/：vault·path·files·search·backup     │
│  plugins/：管理器 + native 加载器 + JSON-RPC 子进程桥        │
│  rpc/：协议类型（NDJSON 编解码）              │
└─────────────────────────────────────────────┘
```

## 3. Rust 后端逻辑

### 3.1 命令注册（lib.rs）

所有前端可调功能都在 `generate_handler!` 注册。每个 `#[tauri::command]` 就是前端 `invoke("命令名", 参数)` 的入口：

```
ping → 链路探针                     vault_get/set → 工作区（含 ensure_vault_matches 服务端校验）
plugins_list/set_enabled/reload/uninstall/read_file/invoke → 插件系统
plugin_call → 统一插件命令路由（native → FFI / process → JSON-RPC）
search_all → 聚合搜索（宿主 FTS + 插件 search.provide）
backup_now/config_get/config_set/list/restore → 自动备份
float_toggle/set_locked → 桌面浮窗      open_in_explorer → 打开资源管理器
```

业务命令（笔记 notes.* / 待办 todos.* / 清单 chk.* / 项目 projects.* / 博客 blog.* / AI ai.*）
不再作为宿主命令注册——全部经 `plugin_call` 分发到核心插件（`src-tauri/src/plugins/mod.rs` 与各插件 `lib.rs` 的 `call` 分发函数）。

阻塞命令（网络、子进程、大目录扫描）均为 `async fn`，跑在异步运行时线程，不冻结 UI。

### 3.2 路径安全（core/path.rs）

所有文件操作走 `resolve_safe(vault, rel)`：
- 拒绝空串、`.`、`..`、绝对路径、盘符前缀
- 规范化后复核仍在工作区内（防符号链接逃逸）

UI 统一用 `/` 分隔的相对路径，Rust 侧转绝对路径再操作。

### 3.3 插件系统

```
plugin.json（清单）→ 管理器发现 → 按 runtime 分三类：

webview 插件（JS）：   前端读入口 JS → Blob URL <script> 注入（CSP script-src blob: 允许，
                      new Function 会被 CSP 拦截）→ api.app.registerCommand 注册命令 → 命令注册表
process 插件（Python 等）：Rust spawn 子进程（cwd=插件目录）
                      → JSON-RPC over stdio（每行一个 JSON）
                      → 核心发 {id, method:"call", params:{command,args}}
                      → 插件回 {id, result} / {id, error}
                      → 插件可反向调核心 API（fs.readText 等，按权限放行）
                      → **解释器三级解析**（目标机无需装 Python）：
                        插件目录自带 python.exe → 全局捆绑运行时
                        （%APPDATA%/com.toolbox.desktop/python/，随包分发）→ 系统 PATH
native 插件（Rust DLL）：libloading 加载 cdylib（仅限 plugins\_core\ 容器，见 3.7）
                      → C ABI 函数调用（FFI，微秒级）
```

生命周期：`启动 → init 握手（返回命令列表）→ 就绪 → 调用/事件 → shutdown`。
健壮性：调用 30s 超时、崩溃/连续超时自动重启（窗口期 60s 限 3 次）、Drop 兜底回收子进程。

**任意语言（Lua/Go/…）的落点**：实现"读 stdin 一行 JSON、写 stdout 一行 JSON"即可成为 process 插件。
**第三方插件开发**：见 `docs/插件开发指南.md`（DLL / TS / Python 三种完整教程）。

### 3.4 配置存储

| 数据 | 位置 | 说明 |
|---|---|---|
| 工作区路径 | `%APPDATA%\com.toolbox.desktop\vault.json` | 全局配置，与数据分离 |
| 应用设置 | 同目录 `app.json` | 通用键值：`closeBehavior`（关闭主窗口：tray/quit）、`trayEnabled`（托盘图标开关）、`closeAsk`（关闭前询问）等 |

「安装 .zip / 安装目录」或复制到插件目录安装。

### 3.6 全文搜索（core/search.rs，SQLite FTS5）

大 vault 下线性扫描（每文件读 256KB + 内存 lower）太慢，改用 **SQLite FTS5 倒排索引**：

- **索引文件**：`工作区\.toolbox\search-fts.sqlite`（派生数据，不进备份；笔记才是真源，删掉索引下次搜索自动重建）
- **分词器用 `trigram`**：文本切成 3-gram 序列，天然支持中文子串匹配——`unicode61` 会把"工作日报"当整个 token，"工作"根本搜不到；trigram 则把 "工作日报" 拆成 "工作日/作日报" 连续匹配。代价是 **<3 字符的查询拆不出 trigram**，自动回退内容 LIKE 线性扫描
- **索引范围**：vault 根下全部 `.md`（排除 `.git/.toolbox/node_modules/target/site`；清单/待办等旧功能的 json 特判已随 2026-08 功能移除删除）
- **拼音匹配**：索引存文件名全拼 + 首字母（`项目计划` → `xiangmujihua` / `xmjh`），`xmjh`、`xiangmu`、`xm jh` 都能命中；ASCII 混排（"API 计划" 搜 `api`）也支持
- **增量同步 + 缓存**：搜索前先同步索引（只重建 mtime/size 变化的条目）；连续搜索 3s 窗口内用**目录树签名**跳过全量 stat（新增/删除文件零延迟，空结果强制重同步兜底内容修改）
- **排序**：文件名匹配 → 拼音匹配 → 内容命中（精确命中优先）；各阶段内按**修改时间降序**（最近改的在前）；整体上限 200 条（文件名命中占满后不再收集内容命中）
- **查询流程**：文件名 LIKE 匹配优先（秒出），≥3 字符内容走 FTS MATCH（短语 = trigram 序列连续匹配 = 精确子串），命中后只对命中的文件读一次前 256KB 切 snippet
- **聚合**：`search_all` 同时聚合启用插件的 `search.provide`（来源徽章标记）；FTS 与提供者调用**并行**执行（FTS 在独立线程，不占插件锁）
- **实测**（3000 篇笔记）：首次搜索含全量建索引 ~3.8s，热查询 ~200ms（含全量 stat）；线性扫描在相同规模下每次都要读全部文件内容
- **依赖注意**：`rusqlite` 必须用 `bundled-full` 特性——普通 `bundled` 不带 FTS5（SQLITE_ENABLE_FTS5 编译宏）

### 3.7 核心插件 cdylib（教学示例 core-example）

核心插件 = 随应用分发的 native 插件（cdylib DLL，宿主进程内 FFI）。**教学基线仅保留
core-example**（`core-plugins/example/`，覆盖全部实现要点，教程见
[docs/核心插件示例教程.md](核心插件示例教程.md)）；新核心插件照它写。

- **契约（tb-sdk）**：插件导出 `tb_abi_version / tb_create / tb_call / tb_free_string / tb_destroy` 五个符号；`tb_create` 收配置 JSON（vault 路径 + manifest config）+ 宿主服务表 `TbHostApi`（`emit_event` / `log` / `open_path` 回调，回调的 ctx = 宿主分配的插件上下文，**插件只透传不解引用**）；`tb_call(method, params_json)` 返回统一 `{ok, result|error}` JSON；`tb_plugin!` 宏生成全部样板（含 `catch_unwind` panic 隔离）；tb-sdk 还内置路径安全（resolve_safe）与本地时间工具
- **性能定位**：宿主进程内 FFI + JSON 序列化（微秒级），介于"编译进宿主"与"进程插件（毫秒级 IPC）"之间，是外部可替换实现里最快的通道
- **目录**：`%APPDATA%\com.toolbox.desktop\plugins\_core\<id>\`；`pnpm build:core` 构建 + 部署（自动清理已不在构建清单中的旧随包插件）
- **默认启用**：核心插件**默认启用**，显式禁用记入 `plugins.json` 的 `disabled` 数组
- **生命周期**：启用/禁用 = 加载/释放 DLL（`Drop` 销毁实例 + 释放句柄）；热重载 = 停+启；插件页"核心"徽章；**可真实卸载**（物理删除 + `removed_core` 标记防随应用重启复活）并可从插件页一键**重新安装**（从随应用分发资源恢复）
- **统一路由**：`plugin_call(id, command, args)` 分发三种运行时（native → FFI；process → JSON-RPC；webview → 前端注册表）；api.ts 全部透明转发
- **插件自带前端（组件模式）**：manifest `ui.entry` 声明插件自带界面（如 `ui/index.js`）；构建时把插件前端（`core-plugins/<id>/ui/`，Vue 3 + TS）打成**自包含 IIFE bundle**（Vue 打进产物，普通插件约 40KB gzip）放进插件目录 `ui/`；宿主 `PluginUiView` 经 `plugins_read_file` 读入口 → Blob URL `<script>` 注入（与 webview 插件同机制，CSP `script-src blob:` 已允许）→ 插件注册 `window.__TB_PLUGIN_UI__[id]` → 宿主把统一 api 桥注入，插件 `createApp(App, { api }).mount(el)` 挂载到容器。插件界面与宿主 Vue 应用同进程直接渲染（非 iframe）；宿主回退视图已随死代码清理删除（插件禁用时显示占位引导）
- **统一 api 桥**：`buildBridgeApi(pluginId, getVault, opts?)` → `call(command, args?, targetPluginId?)`（默认调本插件，可跨插件）、`on(event, cb, targetPluginId?)`（订阅 plugin-event，可跨插件）、`context.vault`（+ 宿主快照 activePath/activeContent）、`nav`（主窗口可用：`go` 跨视图跳转）、`host`（主窗口可用：`search(query)` 调宿主内嵌全文搜索）。插件界面内禁 import 宿主模块，图标内联、样式复用宿主全局 CSS（CSS 变量随主题自适应）
- **宿主内框架（系统级能力，不插件化）**：vault 工作区、**文件服务**（`core/files.rs`，vault 内文件列表/读写/增删改，插件核心 API 与宿主数据层共用）、搜索（SQLite FTS5 + 搜索提供者聚合）、自动备份；前端经宿主命令调用（`files_*` / `search_all` / `backup_*`），插件界面经统一桥 `host.search` 复用
- **事件**：`host.emit_event` → 宿主转发 `plugin-event`（如 example-changed），任意窗口/插件可 `api.on` 订阅保持多窗口一致
- **安全模型**：核心插件是信任代码（随应用分发），`catch_unwind` 隔离 panic；不做沙箱（与外部插件权限门控不同）

## 4. 前端逻辑

### 4.1 状态层（core/）

```
VaultProvider    → 工作区：path/files/activePath/content/dirty/recent/query
PluginProvider   → 插件列表 + 命令注册表 + invoke 路由
NavProvider      → 跨视图跳转（App 层提供）
```

数据层说明：清单/待办/项目等业务数据已并入各插件自带前端（api 桥调用，不再有宿主 Provider）；宿主状态只剩 vault / plugins / 导航配置。

### 4.2 视图层（views/ + components/）

| 视图 | 职责 |
|---|---|
| PluginUiView | 插件的**统一容器**：读插件 `ui/index.js` → Blob 注入 → api 桥挂载（主界面 / 设置面板 / 浮窗共用） |

## 6. 打包成发布版软件

### 6.1 构建安装包

```powershell
# 在项目根目录执行
pnpm fetch:python       # 下载捆绑 Python 运行时（python-build-standalone full，含 pip；
                        # 慢时加 --mirror https://ghfast.top/；产物 src-tauri/resources/python/）
pnpm build:core:release # 构建核心插件 release DLL + ui → src-tauri/resources/_core/
pnpm tauri build
```

流程：`beforeBuildCommand`（`pnpm build:core:release` + `pnpm build`：tsc 类型检查 + vite 打包前端到 `dist/`）→ Rust 编译 release 版 → 打包。
配置在 `tauri.conf.json` 的 `bundle`：目标 **NSIS 安装包**；`resources: ["resources/_core", "resources/python"]` 把核心插件与捆绑 Python 运行时打进安装包。
**目标机无需安装 Python**：process 插件（Python）的解释器按三级解析——插件目录自带
`python.exe` → 全局捆绑（打包版首启部署到 `%APPDATA%\com.toolbox.desktop\python\`）→ 系统 PATH。
**插件依赖自助安装**：插件目录带 `requirements.txt` 时，插件页该插件卡片会出现「安装依赖」
按钮——用捆绑 Python 的 pip 执行 `pip install --target <插件>/vendor -r requirements.txt`，
装完自动重新加载插件生效（需有网；输出尾部会回显）。
**安装后首次启动**：宿主 `ensure_core_plugins` 把安装包资源里的 `_core` 部署到
`%APPDATA%\com.toolbox.desktop\plugins\_core\`（逐插件覆盖部署，用户手动安装的 DLL 插件保留）——用户无需手动装核心插件。
**打包自检**：`pnpm tauri build --debug --no-bundle` 后直接运行
`target\debug\toolbox.exe`（需保证 exe 旁 `resources\_core` 存在——`--no-bundle` 不复制资源，可手动从 `src-tauri\resources` 复制或直接安装验证），
看日志应出现 `[plugin] 已部署随应用分发的核心插件`，
插件页核心插件就绪（资源路径为 `resource_dir/resources/_core`）。

产物位置：`src-tauri\target\release\bundle\nsis\ToolBox_0.1.0_x64-setup.exe`。

### 6.4 安全配置（打包版 CSP）

发布版内置了严格的 **Content-Security-Policy**（在 `tauri.conf.json` → `app.security.csp`）：

```text
default-src 'self';
script-src 'self' blob:;
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: http: https:;
font-src 'self' data:;
connect-src 'self' ipc: http://ipc.localhost;
object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'
```

逐条理解：

- **`script-src 'self' blob:`**：只允许加载应用自己的脚本 + Blob URL 脚本。**没有 `'unsafe-eval'`**——笔记内容/外部数据即使被注入也无法执行 eval/Function。`blob:` 是给插件系统用的：webview 插件入口不再用 `new Function`（会被 CSP 拦截），而是包成 Blob URL `<script>` 注入执行（见 `src/core/plugins.ts`），插件 API 契约不变
- **`style-src 'self' 'unsafe-inline'`**：md-editor-v3 与主题引擎运行时动态注入 `<style>` 标签，必须放行 inline 样式
- **`img-src ... data: blob: http: https:`**：粘贴图片是 base64（data:）、笔记里可能有外链图片
- **`connect-src 'self' ipc: http://ipc.localhost`**：Tauri 2 的前端⇄Rust IPC 走 `ipc://localhost` 自定义协议；应用所有网络请求（AI 等）都在 Rust 侧发起，前端不需要连外网
- **`object-src/base-uri/frame-ancestors/form-action 'none'`**：关掉插件/嵌入/表单等攻击面

两个关键点（调试时容易踩坑）：

1. **CSP 通过 HTTP 响应头注入，不是 `<meta>` 标签**——Tauri 2 在 `http://tauri.localhost/` 的响应头里下发 CSP，并且自动把自身注入的内联脚本哈希（`'sha256-...'`）追加进 `script-src`。所以 DevTools 里看不到 meta 是正常的
2. **`devCsp: null`**——开发模式完全放开 CSP（Vite HMR 需要内联脚本 + WebSocket），生产才收紧。改 CSP 后必须验证**打包产物**（`pnpm tauri build --debug --no-bundle` + 跑 exe 检查控制台无 "Refused to" 报错）

### 6.5 数据备份/迁移

整个工作区文件夹就是全部数据——复制、换机器粘贴即可。备份 = 完整快照（`工作区\.toolbox\backups\backup-<时间戳>\`），**另含应用配置（%APPDATA% 下各 json）与全局插件目录的存档**（`_config/`、`_plugins/`，防丢失；核心插件 `_core` 随应用分发不占备份空间）。

### 6.6 备份恢复（回滚手段，替代已移除的版本历史）

设置 → 备份 → 备份列表每行显示时间 / 大小 / **内容构成徽章**（配置 / 插件）与"恢复"按钮：

- **恢复**：点"恢复" → 确认。**恢复前自动保存当前状态**（可反悔，现场备份跳过保留份数清理，不会被误删）；然后备份内容复制回工作区
- **语义**：覆盖合并——备份中存在的文件被还原，**备份点之后新增的文件保留**（不做镜像删除，避免误删当前数据）
- **不恢复**：配置/插件存档（仅存档防丢失，恢复仅还原工作区数据，不覆盖当前环境）
- **与备份的关系**：备份 = 最近 N 份完整快照（保留份数可配置），需要"回滚到任意编辑点"的精细历史用备份间隔内的多次备份近似；旧版 git 版本历史已按你的决定移除

- 搜索提供者：任何插件声明 `searchProvider: true` 并实现 `search.provide` 命令即接入全局搜索（来源徽章标记，点击直达对应视图）✅

## 8. 学习建议路线

1. 先读 `PLAN.md`（设计动机）→ `lib.rs`（命令全景）
2. 跟一条数据流：笔记插件界面（`core-plugins/notes/ui/index.ts`）输入 → api 桥 `notes.write` → `plugin_call` → `core-plugins/notes` DLL（`fs::write` 原子写）→ 磁盘；宿主侧 `vault.ts` 监听 notes-changed 刷新文件树

6. 想改界面就进 `views/`（页面）+ `components/`（部件）+ `styles/tokens.css`（所有颜色都是变量）
