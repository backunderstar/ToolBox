# ToolBox 操作手册

> 个人工具箱桌面应用 —— Rust 核心 + 多语言插件系统 + 主题系统。
> 目标功能：笔记、数据工具、清单、记录、项目文件管理、AI 整理、博客发布。

---

## 1. 项目是什么

| 维度 | 内容 |
|---|---|
| 形态 | Windows 桌面应用（Tauri 2 打包，WebView2 渲染） |
| 核心语言 | Rust（文件、进程、AI、HTTP、静态服务器） |
| 界面 | React 19 + TypeScript + Vite 6 |
| 数据 | 纯文件优先：Markdown 笔记 + JSON 清单/记录，可 git、可迁移 |
| 扩展 | 插件系统：JS（界面内）+ Python（子进程） |

**核心架构一句话**：Rust 干"重活"（文件、搜索、AI、插件进程管理、博客生成），WebView 干"好看"（界面、主题），两者通过 Tauri IPC（`invoke` 命令）通信。

```
┌─ WebView UI（React/TS）────────────────────┐
│  视图层：笔记/插件/数据工具/清单/记录/项目/AI/博客/设置 │
│  状态层：vault / plugins / checklists / records │
│  主题引擎：ThemeDef + CSS 变量覆盖            │
└───────────────┬────────────────────────────┘
                │ IPC（invoke / log_console）
┌───────────────┴────────────────────────────┐
│  Rust 核心（Tauri 2）                        │
│  core/：vault·notes·ai·blog·path            │
│  plugins/：管理器 + native 加载器 + JSON-RPC 子进程桥        │
│  rpc/：协议类型（NDJSON 编解码）              │
└─────────────────────────────────────────────┘
```

## 3. Rust 后端逻辑

### 3.1 命令注册（lib.rs）

所有前端可调功能都在 `generate_handler!` 注册。每个 `#[tauri::command]` 就是前端 `invoke("命令名", 参数)` 的入口：

```
ping → 链路探针        vault_get/set → 工作区
fs_list/read/write/create/delete/rename/search → 笔记文件操作
fs_list_dir → 枚举指定目录（清单/记录 JSON 用）
plugins_list/set_enabled/reload/invoke → 插件系统
ai_config_get/set/set_key/clear_key/chat/test → AI（Key 存凭据管理器）
blog_list/generate/preview_start/preview_stop/open_folder → 博客
projects_list/create/archive/unarchive/delete/files/open → 项目文件管理（M8）
backup_now_cmd/config_get/config_set/list → 自动备份（设置页）
open_in_explorer → 打开资源管理器
```

阻塞命令（网络、子进程、大目录扫描）均为 `async fn`，跑在异步运行时线程，不冻结 UI。

### 3.2 路径安全（core/path.rs）

所有文件操作走 `resolve_safe(vault, rel)`：
- 拒绝空串、`.`、`..`、绝对路径、盘符前缀
- 规范化后复核仍在工作区内（防符号链接逃逸）

UI 统一用 `/` 分隔的相对路径，Rust 侧转绝对路径再操作。

### 3.3 插件系统

```
plugin.json（清单）→ 管理器发现 → 按 runtime 分两类：

webview 插件（JS）：  前端读入口 JS → new Function("api", code) 执行
                      → api.app.registerCommand 注册命令 → 命令注册表
process 插件（Python）：Rust spawn 子进程（cwd=插件目录）
                      → JSON-RPC over stdio（每行一个 JSON）
                      → 核心发 {id, method:"call", params:{command,args}}
                      → 插件回 {id, result} / {id, error}
                      → 插件可反向调核心 API（fs.readText 等，按权限放行）
```

生命周期：`启动 → init 握手（返回命令列表）→ 就绪 → 调用/事件 → shutdown`。
健壮性：调用 30s 超时、崩溃/连续超时自动重启（窗口期 60s 限 3 次）、Drop 兜底回收子进程。

**未来支持任意语言（Lua/Go/…）的落点**：只要实现"读 stdin 一行 JSON、写 stdout 一行 JSON"即可。

### 3.4 配置存储（三处）

| 数据 | 位置 | 说明 |
|---|---|---|
| 工作区路径 | `%APPDATA%\com.toolbox.desktop\vault.json` | 全局配置，与数据分离 |
| AI 配置 | 同目录 `ai.json`（仅 baseUrl/模型；**API Key 存系统凭据管理器**） |
| 用户数据 | **工作区文件夹内**（自选） | 笔记 .md、清单/记录 .json、站点 |
| 插件 | `%APPDATA%\com.toolbox.desktop\plugins\`（全局） | 插件是"工具"不是数据：与工作区无关，装一次到处可用；启用状态同目录 plugins.json |

### 3.5 博客（core/blog.rs）

笔记顶部 `--- key: value ---`（frontmatter）→ status 为 `published` 的笔记 → `blog_generate` 生成 `site/`：
- `content/*.md`（Zola 兼容源，直接拷贝原文）
- `public/`（pulldown-cmark 渲染的 HTML + 内置 CSS，可直接部署）
- `config.toml`
- `blog_preview_start` 用 tiny_http 起本地静态服务器

### 3.6 全文搜索（core/search.rs，SQLite FTS5）

大 vault 下线性扫描（每文件读 256KB + 内存 lower）太慢，改用 **SQLite FTS5 倒排索引**：

- **索引文件**：`工作区\.toolbox\search-fts.sqlite`（派生数据，不进备份；笔记才是真源，删掉索引下次搜索自动重建）
- **分词器用 `trigram`**：文本切成 3-gram 序列，天然支持中文子串匹配——`unicode61` 会把"工作日报"当整个 token，"工作"根本搜不到；trigram 则把 "工作日报" 拆成 "工作日/作日报" 连续匹配。代价是 **<3 字符的查询拆不出 trigram**，自动回退内容 LIKE 线性扫描
- **增量同步**：每次搜索先对全部 .md 做 `stat`（mtime_ns + size），与索引表比对，只重建变化的条目、清理已删除的——写文件后立即搜索即可命中，无需手动重建
- **查询流程**：文件名 LIKE 匹配优先（秒出），≥3 字符内容走 FTS MATCH（短语 = trigram 序列连续匹配 = 精确子串），命中后只对命中的文件读一次切 snippet
- **实测**（3000 篇笔记）：首次搜索含全量建索引 ~3.8s，热查询 ~200ms（含全量 stat）；线性扫描在相同规模下每次都要读全部文件内容
- **依赖注意**：`rusqlite` 必须用 `bundled-full` 特性——普通 `bundled` 不带 FTS5（SQLITE_ENABLE_FTS5 编译宏）

### 3.7 核心插件 cdylib（阶段 0）

核心功能（记录起步，笔记/清单/项目迁移中）以**核心插件**形态存在：独立 Rust crate 编译成 cdylib（`tb_records.dll`），宿主用 `libloading` 加载、经 **C ABI** 调用：

- **契约（tb-sdk）**：插件导出 `tb_abi_version / tb_create / tb_call / tb_free_string / tb_destroy` 五个符号；`tb_create` 收配置 JSON（含 vault 路径）+ 宿主服务表 `TbHostApi`（`emit_event` / `log` 回调，回调的 ctx = 宿主分配的插件上下文，**插件只透传不解引用**）；`tb_call(method, params_json)` 返回统一 `{ok, result|error}` JSON；`tb_plugin!` 宏生成全部样板（含 `catch_unwind` panic 隔离）
- **性能定位**：宿主进程内 FFI + JSON 序列化（微秒级），介于"编译进宿主"与"进程插件（毫秒级 IPC）"之间，是外部可替换实现里最快的通道
- **目录**：`%APPDATA%\com.toolbox.desktop\plugins\_core\<id>\`（下划线前缀与外部插件 id 不冲突）；`pnpm build:core` 构建 + 部署
- **生命周期**：启用/禁用 = 加载/释放 DLL（`Drop` 销毁实例 + 释放句柄）；热重载 = 停+启；插件页显示"核心"徽章、不可卸载
- **统一路由**：`plugin_call(id, command, args)` 分发三种运行时（native → FFI；process → JSON-RPC；webview → 前端注册表）
- **事件**：插件调 `host.emit_event` → 宿主转发 `plugin-event`（与进程插件共用事件桥与插件页日志）
- **安全模型**：核心插件是信任代码（随应用分发），`catch_unwind` 隔离 panic；不做沙箱（与外部插件权限门控不同）

## 4. 前端逻辑

### 4.1 状态层（core/）

```
VaultProvider    → 工作区：path/files/activePath/content/dirty/recent/query
PluginProvider   → 插件列表 + 命令注册表 + invoke 路由
ChecklistProvider→ 清单列表 + 当前清单（防抖自动保存）
RecordsProvider  → 记录全量 + 反链索引（useMemo 派生）
NavProvider      → 跨视图跳转（App 层提供）
```

自动保存模式（笔记/清单/记录一致）：输入 → 防抖 800ms → 写盘；切换文件前"冲洗"待保存内容。

### 4.2 视图层（components/）

| 视图 | 职责 |
|---|---|
| NotesView + Editor | Vditor 即时渲染（IR 模式），选中文本可 AI 摘要 |
| PluginsView | 插件管理 + 命令试用台（JSON 参数） |
| ToolsView | 内置数据工具（Base64）+ 插件命令区 |
| ChecklistView / RecordsView | 左右布局：列表 + 编辑器 |
| AIChatView | 对话 + 预设动作（总结/大纲/润色）+ 笔记问答（检索增强） |
| BlogView | 文章列表、发布/撤回、生成站点、预览 |
| SettingsView | 工作区、主题选择器/编辑器、AI 配置、备份、导航栏配置、关于 |
| NavSettings（设置内卡片） | 导航栏顺序/显隐配置：组内上移/下移、隐藏不用的项（"设置"固定显示）、一键恢复默认；配置存 localStorage（`toolbox.nav`），与工作区无关 |

### 4.3 主题系统

`ThemeDef = { id, name, base(亮/暗), tokens(令牌覆盖) }`。切换时设置 `data-theme` + 注入 `<style>` 覆盖 CSS 变量。内置 3 主题 + 自定义主题编辑器（实时预览）。

### 4.4 调试链路

- `?mock=1`：浏览器无 Rust 也能跑（内存/localStorage 模拟）
- `console.error` → 转发到 Rust 终端（log_console）
- scripts/cdp-*.mjs：CDP 驱动 headless Edge 或真实 WebView2 做端到端测试
- ⚠️ **E2E 调试端口限制**：tauri.conf.json 的 `additionalBrowserArgs: --remote-debugging-port=9226` 对**所有** WebView2 生效。多窗口（浮窗）时，浮窗 WebView 绑定同一端口会失败 → 浮窗窗口不显示。**跑 E2E 时浮窗会挂，跑完必须去掉该参数**（生产环境绝不保留）

## 6. 打包成发布版软件

### 6.1 构建安装包

```powershell
# 在项目根目录执行
pnpm tauri build
```

流程：`beforeBuildCommand`（`pnpm build`：tsc 类型检查 + vite 打包前端到 `dist/`）→ Rust 编译 release 版 → 打包。
配置在 `tauri.conf.json` 的 `bundle`：目标 **NSIS 安装包**。

产物位置：`src-tauri\target\release\bundle\nsis\ToolBox_0.1.0_x64-setup.exe`（约 10-20MB）。

### 6.2 安装与运行

- 双击 setup.exe 安装（可选开始菜单/桌面快捷方式）
- 程序文件在安装目录；**所有用户数据都在运行时自选的工作区文件夹**

### 6.3 发布版使用流程

1. **首次启动**：欢迎页 → "进入笔记" → "选择工作区文件夹"（选一个普通文件夹）
2. **记笔记**：文件树新建/打开 `.md`，Vditor 即时渲染，失焦自动保存；**删除笔记进系统回收站**（可恢复，不永久删除）
3. **装插件**：插件文件夹放进全局目录 `%APPDATA%\com.toolbox.desktop\plugins\<插件id>\`（含 plugin.json，仓库 `plugins/` 下有 text-stats/csv-tool 示例）→ 插件页自动发现（目录增删实时生效）→ 启用；**插件与工作区无关**，装一次所有工作区可用；启用状态存同目录 `plugins.json`——分享/下载的 vault 不会自动执行其中的插件进程；**旧版装在工作区 `plugins\` 里的插件首次打开会自动迁移到全局**（复制后工作区目录进回收站）；插件页"卸载"按钮 = 停进程 + 清状态 + 全局插件目录移入回收站；**核心插件**（记录等）在 `plugins\_core\` 子目录，随应用分发、可启用/禁用/热重载、不可卸载，插件页显示"核心"徽章
4. **清单/记录**：左侧新建，自动存到 `工作区\data\checklists\`、`data\records\`
5. **双向链接**：记录/清单里写 `[[笔记路径]]` → 点开跳转；**链接的笔记已删除/改名时显示为删除线**（断链提示）；笔记视图顶部显示"反向链接"
6. **AI**：设置 → AI 提供商 → 填 baseUrl/模型，API Key 输入后保存即写入**系统凭据管理器**（不落盘明文，旧版明文 Key 自动迁移）→ AI 页对话/摘要/问答
7. **博客**：笔记顶部写 `status: published` → 博客页"生成站点" → "预览" → 站点在 `工作区\site\`，把 `public/` 部署到任意静态托管，或换 Zola 构建 `content/` 源
8. **项目文件管理**：项目页新建项目（或把已有文件夹放进 `工作区\projects\`）→ 点进项目浏览文件 → 双击文件用默认应用打开、文件夹开资源管理器；完成的项目点"归档"收进 `projects\archive\`
9. **自动备份与恢复**：设置 → 备份 → 开启自动备份（默认每 30 分钟，可改间隔/保留份数）→ 数据备份到 `工作区\.toolbox\backups\`，也可点"立即备份"（后台执行不卡界面，与自动备份互斥）；**备份含配置与插件存档**（列表行有徽章标记）；备份行"恢复" = 恢复到该备份点（恢复前自动保存现场，覆盖合并保留新增文件）
9b. **搜索**：顶栏搜索框聚合文件全文 + 各启用插件的 `search.provide` 命中（如记录标题/标签/内容），来源徽章标记，点击直达对应视图
10. **桌面浮窗**：顶栏浮窗按钮显示/隐藏半透明**桌面层**小组件（不置顶、不遮挡其他窗口，交互完自动回到底层）→ 输入回车添加待办、点圆圈勾选、点 × 删除；标题栏 🔒 可**锁定位置**（防误拖，锁定时不可拖动/调整大小，状态自动记忆）；**可见性也记忆**——上次隐藏后启动不再弹出；数据存 `工作区\data\todos\todos.json`，与主应用同源

### 6.4 安全配置（打包版 CSP）

发布版内置了严格的 **Content-Security-Policy**（在 `tauri.conf.json` → `app.security.csp`）：

```text
default-src 'self';
script-src 'self' blob:;
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: http: https:;
font-src 'self' data:;
connect-src 'self' ipc: http://ipc.localhost;
object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'
```

逐条理解：

- **`script-src 'self' blob:`**：只允许加载应用自己的脚本 + Blob URL 脚本。**没有 `'unsafe-eval'`**——笔记内容/外部数据即使被注入也无法执行 eval/Function。`blob:` 是给插件系统用的：webview 插件入口不再用 `new Function`（会被 CSP 拦截），而是包成 Blob URL `<script>` 注入执行（见 `src/core/plugins.tsx`），插件 API 契约不变
- **`style-src 'self' 'unsafe-inline'`**：Vditor 渲染时动态注入 `<style>` 标签，必须放行 inline 样式；React 的 style 对象不受影响
- **`img-src ... data: blob: http: https:`**：粘贴图片是 base64（data:）、笔记里可能有外链图片
- **`connect-src 'self' ipc: http://ipc.localhost`**：Tauri 2 的前端⇄Rust IPC 走 `ipc://localhost` 自定义协议；应用所有网络请求（AI 等）都在 Rust 侧发起，前端不需要连外网
- **`object-src/base-uri/frame-ancestors/form-action 'none'`**：关掉插件/嵌入/表单等攻击面

两个关键点（调试时容易踩坑）：

1. **CSP 通过 HTTP 响应头注入，不是 `<meta>` 标签**——Tauri 2 在 `http://tauri.localhost/` 的响应头里下发 CSP，并且自动把自身注入的内联脚本哈希（`'sha256-...'`）追加进 `script-src`。所以 DevTools 里看不到 meta 是正常的
2. **`devCsp: null`**——开发模式完全放开 CSP（Vite HMR 需要内联脚本 + WebSocket），生产才收紧。改 CSP 后必须验证**打包产物**（`pnpm tauri build --debug --no-bundle` + 跑 exe 检查控制台无 "Refused to" 报错）

### 6.5 数据备份/迁移

整个工作区文件夹就是全部数据——复制、换机器粘贴即可。备份 = 完整快照（`工作区\.toolbox\backups\backup-<时间戳>\`），**另含应用配置（%APPDATA% 下各 json）与全局插件目录的存档**（`_config/`、`_plugins/`，防丢失；核心插件 `_core` 随应用分发不占备份空间）。

### 6.6 备份恢复（回滚手段，替代已移除的版本历史）

设置 → 备份 → 备份列表每行显示时间 / 大小 / **内容构成徽章**（配置 / 插件）与"恢复"按钮：

- **恢复**：点"恢复" → 确认。**恢复前自动保存当前状态**（可反悔，现场备份跳过保留份数清理，不会被误删）；然后备份内容复制回工作区
- **语义**：覆盖合并——备份中存在的文件被还原，**备份点之后新增的文件保留**（不做镜像删除，避免误删当前数据）
- **不恢复**：配置/插件存档（仅存档防丢失，恢复仅还原工作区数据，不覆盖当前环境）
- **与备份的关系**：备份 = 最近 N 份完整快照（保留份数可配置），需要"回滚到任意编辑点"的精细历史用备份间隔内的多次备份近似；旧版 git 版本历史已按你的决定移除
