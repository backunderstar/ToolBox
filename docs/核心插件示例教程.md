# 核心插件示例教程（core-example）

> 照着 `core-plugins/example/` 这一个插件，学会 ToolBox **全部核心插件实现要点**。
> 看完本教程 + 源码，就能从零写一个新核心插件（如"记账本"、"RSS 阅读器"）。

## 0. 核心插件是什么

核心插件 = 随应用分发的 **native 插件**：

- 编译为 **cdylib 动态库**（Windows `.dll`），由宿主用 `libloading` 加载进**宿主进程**，
  经 C ABI 调用——性能接近进程内直接调用（FFI + JSON 序列化，微秒级）
- 同时保持"插件"形态：可启用/禁用/热重载/被卸载（卸载后可从资源一键恢复）
- 自带前端（Vue 3）随插件目录分发，宿主注入挂载
- 数据 = vault 工作区里的**普通文件**（JSON/Markdown），用户可直接编辑、备份、迁移

**与 process（Python）插件的区别**：native 是进程内 FFI（快、随包分发、信任代码）；
process 是子进程 JSON-RPC（隔离、可装第三方依赖）。功能定位：**宿主级、随包分发**的
业务插件用 native；脚本化、外部插件用 process/webview。

## 1. 目录结构

```
core-plugins/example/
├── Cargo.toml          # crate 定义（cdylib + tb-sdk 依赖）
├── src/
│   ├── lib.rs          # 插件样板：State + 构造 + 命令分发 + 宿主能力 + 搜索提供者
│   └── data.rs         # 数据层：vault 文件真源（原子写/损坏隔离）+ 单测
└── ui/                 # 自带前端（Vue 3）
    ├── index.ts        # 注册契约 __TB_PLUGIN_UI__["core-example"]
    ├── App.vue         # 界面：列表/添加/切换/删除 + 桥能力演示
    ├── bridge.ts       # 桥 API 类型（.vue 的 <script setup> 不能导出类型）
    └── style.css       # 插件私有样式（Vite 提取，宿主注入）
```

manifest（`plugin.json`）**不手写**，由 `scripts/build-core.mjs` 从 `PLUGINS` 数组生成：
id / name / version / runtime=native / command=[DLL 名] / description / searchProvider /
system / ui / nav / config / bundled 标记。新插件 = 在 `core-plugins/<id>/` 写 crate + ui，
然后往 `build-core.mjs` 的 `PLUGINS` 加一项。

## 2. 逐个文件讲解

### 2.1 Cargo.toml

```toml
[lib]
crate-type = ["cdylib"]        # 关键：编译为动态库（Windows .dll）

[dependencies]
tb-sdk = { path = "../../tb-sdk" }   # 宿主↔插件 C ABI 契约与开发样板
serde = { version = "1", features = ["derive"] }
serde_json = "1"
trash = "5"                          # 删除进回收站（数据安全）
```

- crate 名 = `tb-<id>`（如 `tb-example`），DLL 名 = `tb_<id>.dll`
- 加入 workspace：`Cargo.toml` 的 `members` 加 `"core-plugins/example"`
- 版本同步：`scripts/sync-version.mjs` 的 crates 列表加一项（升版只改 package.json）

### 2.2 src/lib.rs（插件样板，最核心）

三样东西即可生成完整插件：

```rust
pub struct ExampleState { vault: String, author: String }   // 1. 实例状态

fn state_from_cfg(cfg: &Value) -> Result<ExampleState, String>  // 2. 由配置构造
fn call(state, host, ctx, method, params) -> Result<Value, String>  // 3. 命令分发

tb_plugin!(ExampleState, state_from_cfg, call);   // 生成全部 C ABI 样板
```

**`tb_plugin!` 宏**（tb-sdk 提供）生成 5 个 `#[no_mangle] extern "C"` 导出：

| 符号 | 作用 |
|---|---|
| `tb_abi_version()` | ABI 契约版本（不匹配宿主拒绝加载） |
| `tb_create(cfg, host)` | 创建实例（cfg = manifest config + 运行期注入的 vault） |
| `tb_call(h, method, params)` | 调用命令（返回结果 JSON，宿主负责释放） |
| `tb_free_string(s)` | 释放返回字符串 |
| `tb_destroy(h)` | 销毁实例 |

`tb_call` 内部 `catch_unwind` 隔离 panic——插件崩了返回错误 JSON，**不崩宿主**。

**命令分发 `call`** 覆盖的知识点：

1. **业务 CRUD**：`example.list/add/toggle/delete`——读写 vault 数据文件，写操作成功后
   `tb_sdk::emit(host, ctx, "example-changed", {...})` 广播事件（见 2.4）
2. **参数 + 中文 UTF-8**：`example.echo`——JSON 全程 UTF-8，无需额外处理
3. **配置回显**：`example.info`——读 `state.author`（来自 manifest config）
4. **宿主能力**（`TbHostApi` 回调表）：
   - `tb_sdk::log(host, ctx, level, msg)` → 宿主日志（dev 终端 `[plugin]` 前缀行）
   - `host.open_path(ctx, path)` → 用系统默认应用打开路径（Windows 资源管理器）
5. **搜索提供者**：`search.provide`——manifest 声明 `searchProvider: true` 后，
   宿主 `search_all` 聚合时调用；返回 `[{filename, snippet, path}]`
6. **错误**：返回 `Err(...)` 会转成 `{"ok": false, "error": ...}`，前端 `api.call` 抛异常

**生命周期约束（重要）**：`ctx`/`host` 是宿主分配、随实例释放的句柄——`emit`/`log`
**只能在实例存活期间（命令调用栈内）调用**，不要泄漏到自建后台线程（use-after-free）。

### 2.3 src/data.rs（数据层）

教学点：**vault 文件为唯一真源 + 原子写 + 损坏隔离**：

- 数据文件 = vault 里普通 JSON（`data/example/items.json`），用户可直接编辑/备份
- 写入原子写（临时文件 + rename）：崩溃/断电不留半截文件
- 文件损坏 → **隔离改名保留现场**（`.corrupt-<时间戳>`），不覆盖用户数据
- 纯函数 + `#[cfg(test)]` 单测：不依赖宿主与 FFI，`cargo test` 直接测

### 2.4 ui/（自带前端，Vue 3）

**注册契约**（index.ts）——所有插件 UI 一致：

```ts
window.__TB_PLUGIN_UI__["core-example"] = {
  mount(el, api) { app = createApp(App, { api }); app.mount(el); },
  unmount() { app?.unmount(); },
};
```

**桥 `api`**（bridge.ts 声明类型；`.vue` 的 `<script setup>` 不能导出类型，故单独建文件）：

| 能力 | 说明 |
|---|---|
| `api.call(command, args, targetPluginId?)` | 调插件命令（默认本插件；可跨插件调用） |
| `api.on(event, cb, targetPluginId?)` | 订阅插件事件（多窗口一致刷新） |
| `api.context.vault` | 宿主上下文快照（当前工作区路径；惰性 getter 始终最新） |
| `api.nav.go(view)` | 跨视图导航 |
| `api.host.search(query)` | 宿主聚合搜索（FTS + 搜索提供者） |

App.vue 教学点：命令在途守卫（读-改-写异步命令，busy 拒绝并发防丢数据）、
错误可见反馈（不静默吞错）、复用宿主全局 CSS 变量 + 插件私有 style.css。

### 2.5 构建与部署

```bash
pnpm build:core          # debug DLL + ui → %APPDATA%/…/plugins/_core/<id>/（dev 用）
pnpm build:core:release  # release DLL + ui → src-tauri/resources/_core/<id>/（打包用）
pnpm tauri dev           # 启动应用
```

`build-core.mjs` 生成 manifest（含 `bundled: true` 标记）、构建 DLL + Vue UI（Vite lib
模式 → 自包含 IIFE）、部署、自检（plugin.json + DLL 必须存在）。dev 构建会清理
"已不在 PLUGINS 中的旧随包插件"（按 bundled 标记识别，不误删手动安装的插件）。

## 3. 验证与常见问题

- **crate 单测**：`cargo test -p tb-example`（数据层）
- **宿主集成测试**：`cargo test`（mod.rs 有 native_plugin_load_and_call，加载真实 DLL）
- **UI 不经 vue-tsc**：改 ui 后靠 `pnpm build:core` 构建成功 + dev 冒烟验证
- **`process is not defined`**：插件 UI 构建产物必须经 plugin-ui-build.mjs（内含
  `define: {"process.env.NODE_ENV": ...}`）；手写/旧构建器产物会残留 `process.env`
- **数据对象里绝不存 tauri 类型**（AppHandle 等）：只存纯 std 数据（路径/配置），
  否则测试二进制加载即崩 0xC0000139（历史教训，见 HANDOVER §6.1）

## 4. 照猫画虎：写一个新核心插件

1. `core-plugins/<id>/` 建 Cargo.toml（cdylib + tb-sdk）+ src/lib.rs（照 2.2）+ src/data.rs（照 2.3）
2. 需要界面 → ui/（照 2.4）；`build-core.mjs` 的 PLUGINS 加一项（含 nav/ui/config/searchProvider）
3. `Cargo.toml` members + `sync-version.mjs` crates 加一项
4. `pnpm build:core` → 插件页出现 → 启用 → 完成
