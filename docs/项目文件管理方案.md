## 2. 目录结构（纯文件优先）

```
vault/
├── notes/                    # 笔记（已有）
├── projects/                 # ★ 项目文件管理
│   ├── 网站重构/             # 进行中项目 = 普通文件夹
│   │   ├── 设计稿/ 代码/ 需求文档.docx …
│   ├── 客户报价/
│   └── archive/              # 归档区
│       └── 2025 年报/
└── …
```

- **无索引/元数据文件**：项目列表 = `projects/` 与 `projects/archive/` 的直接子目录
- 归档重名：`archive/项目名-2`、`-3` 自动递增
- 文件树：仅浏览，不隐藏点文件（项目文件是用户自己的，不按笔记规则过滤）

## 3. Rust API 设计（`src-tauri/src/core/projects.rs`）

### 3.1 命令签名

```rust
/// 项目列表：进行中 + 已归档（各带文件数）
#[tauri::command]
pub async fn projects_list(vault: String) -> Result<Vec<ProjectInfo>, String>
// ProjectInfo { name: String, archived: bool, file_count: usize }

/// 创建项目文件夹 projects/<name>/
#[tauri::command]
pub async fn projects_create(vault: String, name: String) -> Result<(), String>

/// 归档：projects/<name>/ → projects/archive/<name>/（重名自动加 -2/-3）
#[tauri::command]
pub async fn projects_archive(vault: String, name: String) -> Result<(), String>

/// 还原：projects/archive/<name>/ → projects/<name>/
#[tauri::command]
pub async fn projects_unarchive(vault: String, name: String) -> Result<(), String>

/// 删除项目（默认进系统回收站；permanent=true 物理删除）
#[tauri::command]
pub async fn projects_delete(vault: String, name: String, permanent: bool) -> Result<(), String>

/// 项目内文件列表（一层；dir 相对项目根，"" = 根目录）
#[tauri::command]
pub async fn projects_files(vault: String, name: String, dir: String) -> Result<Vec<ProjectFile>, String>
// ProjectFile { name, path(相对项目根,/分隔), is_dir, size: Option<u64> }

/// 用默认应用打开文件 / 资源管理器打开文件夹
#[tauri::command]
pub async fn projects_open(vault: String, name: String, rel: String) -> Result<(), String>
```

### 3.2 安全与校验（复用 `core::path` 思路）

- `validate_project_name(name)`：
  - trim 后非空，长度 ≤ 128
  - 禁止字符：`/ \ : * ? " < > |`（Windows 保留）及控制字符
  - 禁止 `.` `..` 开头（隐藏目录 / 越界）
- `resolve_in_project(vault, name, rel)`：
  - `projects/<name>/` 为根，`rel` 必须解析后仍落在根内（复用 canonical-parent 检查）
  - 拒绝 `rel` 为空 / `.` / `..` / 绝对路径
- `projects_open` 的 `rel` 同规则；**只允许打开，不允许写入/删除项目内文件**（一期）

### 3.3 错误信息约定

| 场景 | 错误文案 |
|---|---|
| 项目名非法 | `项目名不合法: <name>` |
| 项目不存在 | `项目不存在: <name>` |
| 重名创建 | `项目已存在: <name>` |
| 归档重名 | 自动加后缀（不报错） |
| 打开文件不存在 | `文件不存在: <rel>` |
| 越界 | `路径越界` |

### 3.4 依赖

```toml
# src-tauri/Cargo.toml 新增
trash = "5"        # 回收站删除（Windows/macOS/Linux 统一）
```
- 打开文件用**已有** `tauri-plugin-opener`（`open_path`），capabilities 已含 `opener:default`，无需新增权限

## 4. 前端设计

### 4.1 状态层（`src/core/projects.tsx`）

```ts
interface ProjectInfo { name: string; archived: boolean; fileCount: number }
interface ProjectFile { name: string; path: string; isDir: boolean; size: number | null }

interface ProjectContextValue {
  projects: ProjectInfo[];        // 全部项目（含归档）
  loading: boolean;
  refresh: () => Promise<void>;
  create: (name: string) => Promise<void>;
  archive: (name: string) => Promise<void>;
  unarchive: (name: string) => Promise<void>;
  remove: (name: string) => Promise<void>;
  // 详情页状态
  current: string | null;         // 当前打开的项目名
  cwd: string;                    // 当前目录（相对项目根）
  files: ProjectFile[] | null;
  openProject: (name: string) => Promise<void>;
  enterDir: (rel: string) => Promise<void>;
  backDir: () => void;            // 面包屑回退
  openFile: (rel: string) => Promise<void>;   // 默认应用打开
}
```

- 列表与文件浏览各走一次 invoke，不做本地缓存副本（文件为真源）
- 复用 `useVault().path` 拿工作区路径；无工作区时项目页显示引导

### 4.2 组件树

```
ProjectsView
├── ProjectListPage（current === null 时）
│   ├── header：标题 + 新建输入（回车创建）
│   ├── section 进行中：ProjectCard[]
│   └── section 已归档：ProjectCard[]（按钮变"还原"）
└── ProjectDetailPage（current 非空时）
    ├── 顶栏：←全部项目 / 项目名 / 真实路径
    ├── 面包屑：根 ▸ 子目录 ▸ …
    └── FileList
        ├── 文件夹行：📁 名称（点击进入；行尾按钮"在资源管理器打开"）
        └── 文件行：📄 名称 + 大小（点击 → openFile）
```

### 4.3 交互细节

| 操作 | 行为 |
|---|---|
| 新建项目 | 输入名回车 → `create` → 刷新 → 状态栏提示；空名/非法名显示错误 |
| 归档 / 还原 | 直接执行 + 状态栏提示（不弹确认，可撤销=还原） |
| 删除 | `confirm("删除项目 X？将移入回收站")` → `remove` |
| 打开文件 | `openFile(rel)` → 系统默认应用；失败（文件被删）→ 错误提示 + 刷新列表 |
| 进入文件夹 | `enterDir(rel)` → 加载子目录；面包屑可逐级返回 |
| 打开文件夹 | 行尾按钮 → 资源管理器打开该目录 |

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 项目名非法/越界 | 破坏目录结构 | Rust 强校验 + 单测 |
| 归档重名 | 覆盖已有项目 | 自动数字后缀 |
| 删除误操作 | 不可恢复 | 默认回收站 + 二次确认 |
| 大项目枚举卡 UI | 文件很多 | 命令 async + 一层层按需加载 |
| trash crate 平台差异 | 某些环境回收站失败 | 失败时回退提示"改为永久删除？" |
| 双击文件误开危险文件 | exe 等被执行 | 一期仅提示打开，不自动运行未知类型（open_path 交由系统处理，系统本身有确认机制） |

## 11. 数据安全与备份

- **零转换原则**：应用只浏览/打开项目文件，**不做任何转换/复制/改写**，从根上避免数据损坏
- **删除默认回收站**：`trash::delete` 失败时降级为"提示用户，改为永久删除需显式确认"
- **备份**：项目随 vault 一起备份（复制整个 `projects/`）；文档中说明"想备份项目 = 备份 vault"
- **权限最小化**：一期命令只读（list/files/open），无 write/delete 项目文件命令；`projects_delete` 仅作用于整个项目目录
