# 项目文件管理 —— 方案计划

> 状态：方案待确认（未实施）
> 关联需求：#3「工作时进行项目文件管理：项目目录、归档，映射文件夹和文件，点击时像在文件夹里一样用默认应用打开」

---

## 1. 需求理解

在 ToolBox 里管理工作中的项目文件：

- **项目**：一个真实文件夹（含各类工作文件：文档 / 表格 / 图片 / 压缩包…）
- **归档**：已完成的项目统一收纳，与进行中的分开
- **映射**：项目视图里看到的文件/文件夹 ↔ 磁盘上的真实位置（所见即所得）
- **打开**：点击文件 → 系统默认应用打开（PDF→阅读器、xlsx→Excel）；点击文件夹 → 资源管理器

预期形态：

```
┌────────────────────────────────────────────┐
│ 项目                          [+ 新建项目]  │
│                                            │
│ ┌ 进行中（2）─────────────────────────────┐ │
│ │ 📁 网站重构    12 个文件   归档 · 删除   │ │
│ │ 📁 客户报价    8 个文件    归档 · 删除   │ │
│ └─────────────────────────────────────────┘ │
│ ┌ 已归档（1）─────────────────────────────┐ │
│ │ 📁 2025 年报    已归档    还原 · 删除    │ │
│ └─────────────────────────────────────────┘ │
└────────────────────────────────────────────┘

点击「网站重构」→ 项目文件浏览器：
┌────────────────────────────────────────────┐
│ ← 全部项目    网站重构（D:\vault\projects\网站重构） │
│  📁 设计稿 / 📁 代码 / 需求文档.docx / 排期.xlsx │
│  （点文件 → 默认应用打开；点文件夹 → 资源管理器）  │
└────────────────────────────────────────────┘
```

## 2. 目录结构（纯文件优先）

```
vault/
├── notes/              # 笔记（已实现）
├── projects/           # ★ 项目文件管理（本方案）
│   ├── <项目名>/       # 进行中项目：每个项目一个真实文件夹
│   │   ├── 任意文件/子目录（用户自由组织）
│   │   └── ...
│   ├── <项目名>/…      # 多个项目
│   └── archive/        # 归档区：已完成项目移动到这里
└── ...
```

- 项目即文件夹，**没有额外索引文件**——归档 = 移动文件夹，还原 = 移回来，天然简单
- 随 vault 一起备份 / git，符合"数据永远是自己的"

> **待确认 1（关键）**：项目文件夹放在 `vault/projects/` 内（推荐，备份简单），
> 还是需要"映射工作区外的任意文件夹"（如 `D:\Work\项目A`，项目记录存 JSON + 外部绝对路径）？
> - 方案 A：vault 内物理管理（推荐，纯文件、零元数据）
> - 方案 B：外部路径映射（更灵活，但归档/删除涉及 vault 外文件，需谨慎）

## 3. Rust 侧设计（新模块 `src-tauri/src/core/projects.rs`）

| 命令 | 说明 |
|---|---|
| `projects_list(vault)` | 枚举 `projects/` 与 `projects/archive/`，返回 `[{ name, archived }]` |
| `projects_create(vault, name)` | 创建 `projects/<name>/`（名校验：防 `..`、防重名） |
| `projects_archive(vault, name)` | `projects/<name>/` → `projects/archive/<name>/`（重名自动加后缀） |
| `projects_unarchive(vault, name)` | 反向移动 |
| `projects_delete(vault, name)` | 删除项目（默认移到**系统回收站**，`trash` crate；待确认） |
| `projects_files(vault, name, dir?)` | 枚举项目内目录（一层，前端按需递归展开） |
| `projects_open_path(vault, rel)` | 用系统默认应用打开文件 / 资源管理器打开文件夹 |

安全要点：
- `resolve_safe` 复用：所有路径必须落在 `projects/` 内（A 模式）
- 项目名校验：禁止空、`.`、`..`、含 `/`、`\`、保留字符
- 归档重名：`archive/项目名-2` 自动去重
- 打开文件用 `tauri-plugin-opener` 的 `openPath`（**已有依赖**，capabilities 已有 `opener:default`）

## 4. 前端设计

### 4.1 导航
侧栏新增「项目」入口（`IconFolder` 或专用图标），视图 id `projects`。

### 4.2 ProjectsView（两级页面）

**① 项目列表页**
- 分两组：进行中 / 已归档（带数量徽章）
- 每项目卡片：名称、文件数、操作按钮（归档 / 还原 / 删除）
- 顶部「新建项目」输入框（回车创建）

**② 项目详情页（文件浏览器）**
- 面包屑：`← 全部项目 / 项目名`
- 文件列表：目录优先，显示名称 + 类型图标 + 大小（可选）
- 点击文件夹 → 展开进入下一层；点击文件 → `projects_open_path` 默认应用打开
- 顶部显示项目真实路径（映射透明化）
- 右键菜单（可选）：在资源管理器中打开、重命名、删除文件（二期）

### 4.3 数据流
- 状态放 `src/core/projects.tsx`（ProjectProvider）：list / files 两级缓存
- 操作走 invoke → Rust 命令；无本地缓存副本（文件为真源）

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 项目名非法 | `..`/斜杠/保留字符越界 | Rust 侧强校验 + 单测 |
| 归档重名 | archive/ 已存在同名 | 自动加数字后缀 |
| 删除误操作 | 直接物理删除不可恢复 | 默认进系统回收站（trash）；UI 二次确认 |
| 大目录枚举卡 UI | 文件树递归慢 | 命令 async；列表按需一层层加载 |
| 外部路径（若选 B） | vault 外文件操作权限/越界 | 仅枚举+打开，不允许删除；路径由用户显式添加 |
